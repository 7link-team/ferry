一个轮询循环条件领取到期任务；同任务已有排队/执行/需核实记录则留跳过历史；服务启动推进停机错过的next_run_at并记录一次跳过说明，不追跑历史。运行结果不确定时需人工核实，禁止自动重放；重试仅针对确定失败，默认0。下游部署/流水线运行ID保留并可跳转。新增资源引用在删除主机/组/流水线/应用时保护，避免悬空计划。历史清理沿用已确认配置并保护活动/需核实记录；告警阶段消费失败记录。

### 阶段4设计：外部仓库索引与应用市场
复用现有repositories（远程URL/branch/credential）与vault，不提供Git托管、编辑或推送。新增marketplace_sources保存repository_id/provider/api_base/project/organization/index_path及同步状态；marketplace_entries保存经现有模板引擎验证的应用模板快照。API以各平台官方contents/files协议读取JSON索引，设置超时、响应大小限制、不跟随重定向，认证按provider发送，错误不含令牌或带token的URL。GitHub/GitLab/Gitee/Codeup支持公共与用户配置令牌的私有源，自托管接入点显式配置；用户URL决定来源，不自动向其他域名转发凭据。
索引技术格式为version=1及templates数组，每项稳定key/name/description/content/parameters；整个索引验证成功才原子替换本地目录，失败保留上次成功数据并显示错误。来源CRUD使用marketplace-sources标准权限，手动同步需marketplace-sources.sync，定时同步复用共享cron_jobs的deploy动作及执行身份/时区/重叠/重试语义，不另建定时系统。导入动作沿用模板创建校验，创建独立模板快照，不自动部署。源变更/删除与正在同步互斥；关联仓库/定时任务删除有引用保护。已有模板不随目录刷新改变。
官方协议依据：GitHub REST repos/contents；GitLab API repository_files；Gitee api/v5/swagger_doc（contents endpoint，access_token query/ref）；Codeup官方GetFileBlobs文档（x-yunxiao-token，组织/仓库/files路径，content和encoding字段）。用户进一步确认优先网页授权，不适用时使用API授权；需实现授权状态、失效与重新授权，复用加密凭据。先推进实现，不等待测试仓库输入。真实私有平台兼容验收仍需实际账号；隔离HTTP夹具只能证明请求/安全/原子同步逻辑，不能替代真实提供方验收。

#### 网页授权集成设计（用户追加确认）
GitHub/GitLab/Gitee采用Authorization Code，GitHub/GitLab启用PKCE S256；Codeup采用官方个人访问令牌API。登录会话绑定发起人、工作空间、单次随机state（数据库只存hash），加密保存短期verifier；回调在事务内消费state后交换令牌，重新核实用户权限，读取账号身份并写入现有credentials。拒绝跨用户/空间回调、重放和过期state；HTTP日志只记录路径，不记录授权query。使用时刷新即将过期token，按workspace锁领取并用版本条件防止并发旧刷新覆盖重新授权；续期失败或进程中断要求重新授权。刷新令牌以vault加密，删除凭据同步删除授权记录；人工不得覆盖网页管理的token。提供仓库授权列表、状态、查看凭据、重新授权和APIfallback入口。
部署端注册OAuth应用，配置 `REPOSITORY_OAUTH_PUBLIC_URL`、`REPOSITORY_OAUTH_{GITHUB|GITLAB|GITEE}_CLIENT_ID` 与 `_CLIENT_SECRET`；可配置 `_BASE_URL` 和 `_API_URL` 接入自托管平台。回调为 `{PUBLIC_URL}/api/repository-auth/callback`，在提供方登记一次即可服务所有工作空间；秘密不进入前端或版本库。GitHub公开默认github.com/api.github.com，GitLab默认gitlab.com/api/v4，Gitee默认gitee.com/api/v5。网页授权当前同窗口跳转以保留登录会话；实际提供方和安装版WebView兼容性仍需真实账号验收，不把隔离OAuthfixture当成第三方已验收。

流水线definition新增`artifacts`相对文件路径数组；成功执行后经HostChannel流式归档到服务端，保存SHA-256、大小、文件模式、所属执行。构建目录后续改写不改变归档；缺失声明文件使构建失败。复用构建读取权限、共享列表和执行详情下载入口，随配置的构建历史清理；默认永久保留。native部署消费这些固定版本的文件，不能再次从可变构建目录读取。

配置文件模板复用templates参数引擎、CRUD/CAS/审计与共享表单，独立config_templates表。任意文本使用`.Values`占位符；secret参数只接收变量名，内部令牌禁止由普通参数或模板文本伪造，预览只显示引用。manifest.files声明path/fromTemplate/values；同空间按ID或唯一名称引用。部署预览固定模板/变量版本，入队时验证并加密保存完整文件；回滚使用历史快照、不重新渲染当前模板。正在引用的模板禁止删除/改名；内容修改令旧预览失效。配置文件以0600挂载只读，运行期间必须保留在目标上（与仅在启动时读取的env_file不同）。

资源CPU支持核数或m、内存支持字节或Ki/Mi/Gi/Ti/K/M/G/T；验证requests不超过limits，Compose资源输出归一化成其实际接受的字符串格式，overrides合并后再次验证。HTTP健康检查的持续liveness映射到容器healthcheck；readiness在部署/重启后按声明周期检查，在healthTimeout内所有实例就绪才保存成功产物。容器镜像需包含sh及curl或wget，原有能力矩阵约束继续显式报错。

目前实测：构建runner/SSH60项通过；健康/资源Compose runner/SSH120项通过；配置模板SQLite22项通过。配置文件真实挂载/回滚、三库、浏览器及后续模式还在测试/实施，不能据此声明阶段5或本轮发布范围完成。首次挂载失败原因是测试夹具使用兄弟容器共享Docker socket但未共享bind路径；改用同一Docker卷在daemon实际路径挂载，仍按真实文件和容器断言验证，未放宽产品断言。

### Native 实施与验收边界
Native 使用现有 HostChannel 上传流水线归档的可执行文件，部署预览固定构建执行和 SHA-256，入队建立历史引用，历史仍引用的构建不受构建历史清理影响。配置模板与变量继续使用同一加密快照；systemd 的 EnvironmentFile 必须保留供主机重启使用。每个服务一份 systemd unit，CPUQuota/MemoryMax、命名目录持久卷、只读配置挂载及依赖顺序沿用统一 manifest。健康检查按既定能力矩阵映射 ExecStartPost 和 Restart=on-failure，不宣称独立持续就绪探针。

完整 unit 与探针脚本一起保存在部署产物；回滚不重新渲染。`overrides.native.units` 可按服务名替换完整 unit。安装前检查单元归属，拒绝覆盖不属于该应用的单元；远端 flock 和产物摘要防止并发覆盖。真实验收使用自有 systemd Linux 容器，经 runner 和 SSH 分别部署可执行 HTTP 服务、更新、回滚、配置/密钥恢复、重启和健康失败。K8s/Helm 仍暂缓。

### Swarm 实施设计
`stack` 模式复用容器 manifest/镜像摘要解析及 HostChannel，执行原生 `docker stack deploy` 并检查各 service 的期望副本与任务状态；不把提交成功当部署成功。支持 rolling/recreate，rolling 的 maxUnavailable=0 映射 start-first，其余映射 stop-first 并限制更新并发。Swarm 无 depends_on 启动顺序保障，声明该约束时明确拒绝，应用需自身重连。命名卷仍为节点本地数据，不承诺跨节点复制。
配置文件采用按版本命名的 Swarm secret，通过管理节点上传，由 Swarm 分发到任务节点，不将管理节点本地文件 bind 到工作节点。变量从加密快照在执行时生成私有临时 stack 文件，执行后删除；公开历史仅保留引用。回滚重新使用固定镜像/文件快照。部署锁、远端产物摘要、服务/secret 所属标签保护、失败不自动回滚沿用现有执行语义。实测仅创建独立 Docker-in-Docker Swarm，不能将用户当前 Docker daemon 切换为 Swarm。

### 主机组实施设计
沿用主机组直接成员、按主机 ID 排序的既有规则，逐台执行，首个失败停止，已成功主机不自动回滚。预览固定成员列表和每台主机的产物摘要；入队再次验证成员列表，执行期间不重新选择成员。回滚使用历史版本固定的目标列表，不能把旧产物隐式部署给后来加入的成员。

新增部署 revision 的目标明细（主机、顺序、固定产物、预期摘要、状态、输出、起止时间）以及应用每台主机的当前成功 revision。父 revision 保持现有队列/审计/权限/优雅关闭契约；目标明细复用同一个 HostChannel 执行器，不增加第二套模式逻辑。父执行失败保留已成功目标的当前版本，未尝试目标标记跳过。历史清理同时保护各主机当前成功版本，防止部分成功后的产物丢失；删除应用按现有语义仅删除记录和历史，不停止运行服务。

预览返回每台主机的期望摘要；提交与预览 token 绑定整份摘要映射并验证目标一致。共享部署详情展示目标进度、状态、输出及当前版本，不另造资源表格。验收覆盖两台主机成功、第二台失败后第一台保留、未执行目标跳过、预览后成员变化拒绝、排队后成员冻结、逐主机漂移、历史回滚、权限撤回及部分成功历史保留。

### CSV／XLSX 导入导出设计
使用真实 CSV/XLSX 格式，继续共享资源表格工具栏。下载模板提供字段名及说明；导出沿用当前搜索/过滤/排序，分批读取并写临时文件后流式下载，避免全量表格驻留内存。XLSX 使用成熟读写库，不手写 Office ZIP/XML；上传校验压缩包解压大小、行数、重复/未知表头及字段类型。

导入沿用现有“创建”权限和创建语义，只新增，不隐式覆盖已有记录。预览复用各资源正常创建路径：在数据库事务/逐行保存点中执行完整校验及插入，最后整体回滚，所以正常资源和审计均不落库；不会触发远端操作。预览保留原始行号和逐行错误，密钥列不回显。待确认数据按用户/空间/资源绑定后加密保存，用户可取消删除；不引入未确认的定时删除策略。

确认提交时重新检查权限和引用，在同一事务中创建全部记录、记录审计、消费导入单并清空待导入密文；任一行失败全部回滚。重复确认返回原结果，不重复创建。借此复用同一组 create_in 函数，避免导入走一套更弱的校验。只读历史/成员等资源提供导出，不把历史事件、成员邀请或执行操作当成普通资源导入。CSV 文字防公式注入；XLSX 输出文本单元格，不执行上传的公式。

### 最终范围核对：主机标签与分组引用
现有 `host_tags` 只有表结构、没有调用方，本轮补齐主机表单多选标签、列表标签显示/筛选，以及导入导出的标签 ID 数组。复用共享表单 multiselect 与现有标签 CRUD；关联只能引用本空间标签，主机乐观版本检查与关联替换在同一事务。省略 tag_ids 的旧客户端保留原关联，显式空数组清空；删除主机清理关联，删除仍被引用的标签沿用现有资源引用保护规则并提示先移除。分组的 parent_id 补齐同空间校验、环检测及子组删除保护，维持“直接成员”部署规则。验收覆盖三库、CAS、租户边界、导入及实际浏览器选择/过滤。
