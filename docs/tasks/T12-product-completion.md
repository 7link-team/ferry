# T12 — 完整产品功能补齐与验收

## Goal / Requirements
2026-10-26用户明确要求全部剩余功能实现并测试验收，并确认范围为完整产品方案，而不只是补齐导航入口。包括市场、监控、共享定时任务、工作空间配置项、字典、导入导出，以及Docker/native/Swarm/K8s/Helm、构建产物、配置文件、健康/资源限制、主机组逐台部署等未完成能力。原有Compose、变量历史回滚、桌面优雅更新必须保持。

## Confirmed Decisions
- 仓库连接GitHub/GitLab/Gitee/Codeup等外部平台，不建设内部Git托管服务。市场读取外部仓库模板索引；凭据复用加密保管。
- 定时任务显式时区；停机错过的触发不补跑；同一任务重叠跳过并记录；默认不重试，可人工配置重试。
- 历史默认保留；管理员显式配置保留天数后才清理。
- 告警支持站内事件及用户配置Webhook。
- 按阶段真实验收，不以页面存在、纯渲染或静态测试代替功能完成；不擅自发版。

## Existing Implementation / Reuse
Scope、共享resource分页/过滤、ResourceTable/ResourceForm、CAS/事务审计、vault、HostChannel、流水线与Compose执行器、模板参数引擎、desktop drain、三库/浏览器/SSH/runner/Compose真实harness。缺失模块必须沿用这些边界。

## Task Decomposition / Execution Mode
Direct。评估过拆分：共享迁移/资源配置/执行状态与生命周期有交叉；当前不委派。每阶段独立checkpoint/测试/提交，持续推进同一完整目标。
1. 工作空间配置项与字典：类型/校验/默认值、实际消费者、共享页面及权限/审计。
2. 定时任务：三scope一个资源，时区调度/领取锁/重叠/重试/超时/历史，主机命令与既有构建部署执行器接入；优雅退出不丢活动工作。
3. 告警：真实主机指标/执行失败规则、事件状态及Webhook投递结果；仪表盘汇总真实新增数据。
4. 外部仓库与市场：四提供方连接、认证、索引同步、导入模板、定时同步、故障可见；不托管Git仓库。
5. 构建产物与配置文件模板；manifest完整类型及能力矩阵，保密预览/可重复回滚。
6. Docker/native/Swarm执行；主机组逐台、失败即停、逐目标记录；沿用HostChannel与drain。
7. 集群资源与K8s/Helm执行；kubeconfig加密；真实本地集群部署、回滚和故障验证。
8. 通用导入导出：沿用资源授权/校验/审计，秘密不可隐式导出；明确逐行结果及引用错误，不隐藏失败。
9. 全量验收：完整能力清单、三数据库/升级、浏览器、两种主机通道、各部署模式、桌面服务生命周期与发布门禁。

## Files / Design
新增模块按业务职责划分，不新增通用插件框架。追加迁移；扩展现有实体/路由/资源DSL与执行器；按需引入成熟cron/时区/Kubernetes/HTTP库，避免自行实现协议。共用manifest解析并按模式显式校验，纯渲染与实际执行分离，历史保存完整产物与加密引用值。每阶段在本文件补记录具体实现和验收证据。

## Testing / Acceptance Criteria
每个资源覆盖CRUD/租户/权限/CAS/错误与引用校验；每个运行能力覆盖实际成功、失败、超时、重启/优雅退出及必要保密检查。三库和旧数据升级必须通过；UI实际创建并完成业务操作。所有已确认能力完成且无未验收项后才可声明完整交付。无法实测的外部提供方能力如实保留未验收，不以mock证明兼容。

## Risks / Out of Scope
真实外部私有仓库授权需测试凭据；若环境缺少集群则优先创建隔离本地测试集群。后续发现材料性未定义语义先提出具体方案，其他工作继续。用户没有要求新发布，发布及外发通知不由本任务自动触发。Webhook验收使用自有测试接收端。

### 阶段2设计：共享定时任务
一张cron_jobs表保存scope、表达式、IANA时区、启停、目标动作、执行身份、超时与重试、next_run_at；cron_runs保存配置快照、触发类型、计划/开始/结束时间、结果/尝试次数及下游执行ID。三个入口只预设scope。五字段cron按分钟，六字段可指定秒；使用成熟croner与chrono-tz库，测试DST边界，不自写日历算法。
写操作验证目标租户及实际动作权限；编辑后执行身份为编辑者，界面显示。每次自动触发重新读取账号/成员/角色状态；立即执行使用当前操作者。主机/组命令经HostChannel，组内逐台执行；流水线复用触发/队列，部署复用预览和apply。停止服务先停领取再等待当前执行与凭据清理，复用desktop drain。
一个轮询循环条件领取到期任务；同任务已有排队/执行/需核实记录则留跳过历史；服务启动推进停机错过的next_run_at并记录一次跳过说明，不追跑历史。运行结果不确定时需人工核实，禁止自动重放；重试仅针对确定失败，默认0。下游部署/流水线运行ID保留并可跳转。新增资源引用在删除主机/组/流水线/应用时保护，避免悬空计划。历史清理沿用已确认配置并保护活动/需核实记录；告警阶段消费失败记录。
