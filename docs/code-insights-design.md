## 2026-11-03 采集更新

入口已调整为「仓库 → 代码洞察」。新建和编辑洞察不再选择业务流水线或主机。平台 API 优先；接口缺少完整文件差异等数据时，自动使用服务端 Git 补全；普通 Git 仓库直接使用该采集器。已经启动的旧分析流水线继续接收原任务产物，后续采集不再启动业务流水线。

Git 采集复用连接授权、令牌刷新、凭据解密、SQL 任务队列、租约及原有入库校验。服务端保存受锁保护的裸仓库缓存，只获取所有分支的对象和引用，不检出或执行仓库代码。后续 fetch 增量传输对象，已完整采集的 SHA 不重复计算文件差异；令牌轮换不会重建缓存。历史范围、作者映射及七类查询保持原口径。状态页展示实际采集阶段、最近成功时间、重试时间和下次触发时间。

容器镜像包含 Git 与 OpenSSH；独立服务端需要安装 Git，SSH 地址还需要可用的 OpenSSH 和可信主机记录，采集器不关闭主机密钥校验。私有 HTTP 授权、全分支获取及删除分支同步、队列入库和重复执行去重已在隔离实例验证；公网 Hello-World 已通过无流水线/Runner 的实际采集。不能据此宣称所有私有代码平台均已实接。下方早期流水线方案为历史背景，以本节为准。

日期：2026-11-02。用户确认后，独立模型、菜单、配置、作者映射和报表已实现，通过真实采集与多数据库验证。本文对应 alpha.35 的集成功能，与主题、字典和配置项改造联合验收。下文多数据库与 Runner 验证记录来自隔离及联合集成阶段；具体发布状态以 GitHub Release 为准。

## 目标与页面

左侧「构建」下增加独立二级菜单「代码洞察」，进入洞察列表，而不是在每个仓库连接详情里承担全部分析管理。一个洞察代表一组分析范围和独立统计配置；一个仓库可以属于多个洞察，一个洞察可以选择多个连接、多个平台的仓库。

列表与创建/编辑继续使用 ResourceTable / ResourceForm。创建时填写名称、选择有权访问的连接及其中明确的仓库，设置完整历史或可配置的初始天数；默认所有分支。没有选中的仓库不因为连接授权就自动启用分析。仓库数量较多时使用已有分页搜索选择器，服务端验证每项授权，不能一次拉取全量选项。

详情拥有独立仪表盘及总览、贡献者、排行、分支、提交、热力图、周期统计，保持 GitInsight 既有条件和公式；另提供仓库范围、人员映射、同步状态和配置入口。沿用现有报表组件和查询参数，不把它们缩减成单一排行。连接详情保留授权与监控职责，可链接到相关洞察。

## 数据与职责

| 层次 | 责任 | 共享边界 |
| --- | --- | --- |
| 仓库连接 | 授权、平台能力、凭据、访问路径 | 复用现有连接与授权，不由洞察复制凭据 |
| 仓库及来源 | 规范仓库身份、连接可见引用及历史覆盖 | 同工作空间、已验证的同一仓库可共享事实；不同凭据的来源授权与可见引用独立 |
| 提交事实 | SHA、父节点、原始作者、时间、消息、增删行、语言等 | 同一仓库/提交/分析版本只采集和解析一次，不按洞察复制 |
| 洞察 | 名称、仓库关系、历史起点、映射版本、统计配置 | 每个洞察独立 |
| 身份投影 | Git 原始身份对应洞察内的贡献者 | 每个洞察独立，保留原始姓名和邮箱 |
| 仪表盘与查询 | 洞察范围内七类报表及全部过滤条件 | 强制洞察范围与当前访问授权，不能由请求参数扩大 |

建议新增洞察实体和洞察—仓库关系。关系除仓库标识外必须保留已授权的来源连接，不能只凭仓库 ID 绕过连接权限。一个洞察内同一仓库保持唯一；多连接访问同一仓库时不重复累加。平台优先采用稳定仓库 ID，普通 Git 复用既有规范身份，不凭仓库名称或相似 URL 猜测镜像相同。不同工作空间不共享事实。

现有 `repository_analysis_configs` 以 connection_id 为主键，适合采集入口，不适合直接成为洞察实体。当前贡献者和提交作者投影以 workspace/user 为作用域，也必须改为洞察作用域；只给报表加 insight_id 参数仍会导致映射互相影响。

身份投影优先按 `(insight_id, raw_identity_id)` 唯一保存解析结果，通过索引关联提交原始身份，不为每个洞察复制全部提交。原始身份在事实层采用稳定关联，升级时本地回填。别名规则和冲突处理保留现有语义；改映射只更新受影响身份的本地投影，不更改事实、采集游标或任务代次。

## 增量、队列与范围

新洞察默认「定时更新」，使用现有 Cron 编辑器，默认 `0 */4 * * *`（每 4 小时），可配置 IANA 时区，留空按 UTC。也可选择「事件更新」：仓库监控检测变化后入队，默认每天进行一次兜底核对。已有洞察和旧连接配置迁移保留原来的事件行为。首次初始化立即执行；手动同步始终可用，也不会消耗下一次计划时间。

定时洞察忽略普通变更事件的分析触发；仅到期时将所选仓库入队。计划时间持久化并通过工作空间事务互斥推进，停机错过多个执行点时合并执行一次，再计算未来时间。修改 Cron、时区或触发方式不重置采集检查点、重扫历史或打断已有任务。界面显示下次计划更新时间；凭据权限不足等调度错误可见。

事件模式的监控变化或定时模式的到期计划标记共享仓库/来源脏状态，SQL 队列合并重复触发；同仓库采集互斥，跨仓库沿用全局并发上限默认 1。多个洞察复用同一份提交事实。不同授权来源的引用范围和成功检查点保持独立，共享事实不能成为权限绕过通道。若同一仓库被事件洞察和定时洞察共同使用，事件洞察可提前更新共享事实，定时洞察看板也会读到该最新结果；计划控制触发频率，不隔离数据快照。

各洞察的历史范围和实际采集覆盖分开记录。例如 A 从近 90 天初始化，B 勾选完整历史：底层只补足缺失历史，A 的固定起点保持不变，B 在回填完成前显示覆盖不足。后续都是增量；勾选完整历史不代表每天全量重算。请求扩大历史范围时才补齐缺口。

暂停或移除某个洞察的仓库关系，只停止该洞察的需求；其他仍在使用的洞察继续同步。删除洞察不级联删除其他洞察仍依赖的共享事实。事实保留期限沿用现有规则，额外的清理策略另行确定，不在菜单改造中加入。

报表使用洞察仓库集合的 semi-join/EXISTS 约束和唯一提交事实，再关联洞察身份投影。分支多对多关系不能放大提交数或增删行。保留按仓库统计的原有语义；不同仓库的相同 SHA 是否视作同一份跨仓库贡献，沿用既有 GitInsight 口径，不在此变更中静默改变。

新维度如果能由已存事实派生，只增加查询/投影；如果依赖尚未采集的文件级、评审等信息，仍需增加字段或表及有版本的回填。不能承诺以后无需 SQL 或模式变更；扩展字段也不应全部塞进不可索引 JSON。优先规范事实、稳定身份、关联索引和服务端聚合，已有压测不足时再评估预聚合。

## 权限、迁移与验收

洞察共享不能默认为分享创建者的私有连接。延续现有工作空间、连接所有者和凭据访问限制，创建、查询和后台采集都验证当前授权。独立洞察读写/同步权限通过现有角色体系声明；角色迁移必须保持原来的可见范围，不默认扩大访问。若要允许不持有连接权限的同事查看汇总，应作为单独的显式共享需求设计。

现有已配置分析的连接可迁移为对应的独立洞察，保留原有拥有者、仓库范围、历史起点、作者映射、流水线配置、提交事实和检查点。采集事实不重拉。原连接级映射转换为对应洞察的映射，不能直接合并为全局映射。全仓库选择配置必须兼容原来的动态发现语义；新洞察的默认创建方式为明确选仓库。未启用分析的连接不批量创建洞察。

实施顺序为模型与迁移、身份作用域与查询、共享采集需求合并、独立入口与复用页面、实际验收。不得改写已发布迁移；当前未发布的研究模型也需明确兼容升级路径。

验收至少包含：A/B 同仓库只新增一份事实；A/B 不同映射互不影响；90 天与完整历史覆盖并存；跨连接多仓库仪表盘；同洞察重复来源不双计；移除/暂停一个洞察不影响另一个；撤权后不能继续查询或发布越权数据；映射修改不调用远端；所有原报表过滤条件和 SQL 分页保持；旧配置升级不重采；原 API 优先/Runner Git 回退、SQL 并发和监控链路回归。
