# 外部仓库连接与应用市场

只连接已有 GitHub、GitLab、Gitee、Gitea、Codeup 或普通 Git 仓库，不托管 Git。在工作空间创建命名的代码连接，再在流水线拉取代码步骤中选择仓库；每个步骤可使用不同的连接和仓库。

## 创建代码连接

构建 → 凭据只管理构建凭据。主机和应用各有独立的凭据入口，SSH 登录选择器只显示主机凭据；三个模块复用加密存储，但页面、创建归属及选择器不混用。模块作用域保存在凭据上，创建后不可修改。升级保留凭据 ID、密文和已有绑定，主机引用的旧凭据归入主机，应用市场来源引用的归入应用，其余归入构建。

连接详情分为“基本信息”和“仓库列表”两个 Tab。仓库列表按代码平台提供的分页浏览，支持刷新、失败后重试，Tab 与页码保存在 URL；没有可靠总数时仅显示当前页和本页数量。普通 Git 不提供平台仓库目录，在拉取代码步骤填写具体仓库地址。

1. 选择代码来源：GitHub、GitLab、Gitee、Gitea、Codeup 或普通 Git。
2. 代码平台选择网页授权或引用已有令牌凭据。网页授权在弹窗完成后保存该命名连接；个人令牌必须通过平台接口验证并成功读取仓库列表，才会保存为连接。
3. 填写连接名称后创建。Codeup 还需填写组织及实例接入信息。连接创建时不选择仓库或默认分支；缺少凭据时可从表单打开新标签页创建，再回来刷新选择。

令牌错误或没有读取仓库的权限时，界面显示错误，不会仅创建一个凭据就显示“已连接”。仓库列表按页读取；可使用已有连接或在表单中重新授权。重新授权保留原凭据引用。授权记录按工作空间和操作者隔离，仓库绑定的凭据可供该工作空间中有相应权限的任务使用。

普通 Git 可填写 HTTP(S) 或 SSH 地址，引用账号密码、SSH 私钥或令牌凭据，也可连接公开仓库。已存在的代码连接可保持原授权，也可在编辑时替换引用。

## 在构建中使用连接

在流水线任务中添加“拉取代码”步骤，选择仓库连接，即可分页浏览该连接有权访问的仓库与分支。“新建仓库连接”在新标签页打开；返回后刷新连接即可选择。连接本身不绑定固定仓库或默认分支，也不需要先单独创建仓库记录。

为每个 Actions 任务选择执行主机（Runner 或 SSH）或主机组，并填写实际构建命令，例如 `npm ci && npm run build`。主机模式使用执行镜像 `host`，执行主机需要安装 Git 和项目所需工具链。检出步骤可选择分支、标签或提交，命令在任务工作目录执行。拉取失败时后续普通步骤跳过，访问凭据通过临时文件提供并在执行后清理。

新任务默认使用独立工作目录；检出绑定可指定目录，多仓库可分别检出到不同子目录。升级后的流水线保留原有绝对工作目录和已有仓库绑定。仅执行命令的任务无需绑定仓库。仓库凭据也可用于运行步骤中的 Git 命令，日志中的秘密值会脱敏。

通过连接选择新仓库需要 `credentials.read`、`repositories.create` 及相应流水线写权限；执行沿用 `pipelines.run`。

## 平台动态配置

超管在“平台管理 → 平台设置”配置公开访问地址及 GitHub、GitLab、Gitee、Gitea 的 OAuth 应用。**保存后立即生效，无需重启**。各工作空间仅授权自己的账号，不重复配置应用密钥。

先在代码平台创建 OAuth 应用，将平台设置页面显示的回调地址登记到提供方：

```text
https://<平台域名>/api/repository-providers/callback
```

公开访问地址必须是用户浏览器实际访问平台的地址，授权前后使用同一登录会话。应用配置加密存储，密钥从不回显；不勾选替换或留空均保留原密钥。关闭某提供方的网页授权后，该提供方的网页授权凭据不再用于新执行；配置仍保留。个人访问令牌连接独立于 OAuth 应用开关。

| 提供方 | 默认网站地址 | 默认 API 地址 | 网页授权请求权限 |
| --- | --- | --- | --- |
| GitHub | `https://github.com` | `https://api.github.com` | `repo read:user` |
| GitLab | `https://gitlab.com` | `https://gitlab.com/api/v4` | `read_user read_api read_repository` |
| Gitee | `https://gitee.com` | `https://gitee.com/api/v5` | `user_info projects` |
| Gitea | 必须填写实例地址 | 网站地址加 `/api/v1` | `read:user read:repository` |

自建 GitLab/GitHub Enterprise/Gitea 可填写网站和 API 地址；GitHub Enterprise 默认 API 路径为 `/api/v3`。更换应用 ID、网站或 API 接入点后，原网页授权凭据需要重新授权，不能将旧令牌发送到新接入点。更换公开地址会拒绝尚未完成的旧授权流程，请重新发起。

兼容原有环境变量：尚未在网页保存设置时，读取 `REPOSITORY_OAUTH_PUBLIC_URL` 与 `REPOSITORY_OAUTH_{GITHUB|GITLAB|GITEE|GITEA}_{CLIENT_ID|CLIENT_SECRET|BASE_URL|API_URL}`。网页保存后以数据库平台设置为准，关闭网页授权不会重新启用环境变量里的配置。

## 个人访问令牌

令牌由代码平台签发，需具备目标仓库读取权限；不是调用本平台 API 的令牌。GitHub/GitLab/Gitee/Gitea 会验证账号并读取仓库列表，未配置 OAuth 应用也可以使用令牌连接。自建平台在创建表单中填写自定义接入点。

Codeup 使用个人访问令牌。中心版填写组织 ID；默认网站为 `https://codeup.aliyun.com`，API 为 `https://openapi-rdc.aliyuncs.com`。Region 版填写对应的网站和 API 地址，组织 ID 可留空。由于 Codeup 令牌接口不返回 Git 登录用户名，还需填写用于实际拉取的 Git 用户名。连接以成功读取组织内可访问仓库为准。

### Codeup 配置与排查

1. 在云效创建个人访问令牌，授予代码仓库、分支只读权限以及通过 HTTPS 拉取代码所需的权限。令牌权限和账号本身的仓库权限必须同时满足；能列出仓库不代表一定允许 Git 下载。
2. 在当前工作空间的凭据中创建“令牌”凭据，填写 Codeup 的 Git 用户名与令牌。不要把阿里云 AccessKey、本平台登录令牌或 SSH 私钥填到个人访问令牌中。
3. 创建代码连接，选择 Codeup 并引用上述凭据。中心版从云效组织管理后台获取组织 ID；Region 版使用实例域名作为 API 地址，组织 ID 留空。网站地址需与返回的 HTTPS 仓库地址同源。
4. 在流水线的“拉取代码”步骤选择该连接和仓库。仓库和分支均可加载下一页；分页失败可重试当前页。分支输入框也接受标签或完整提交 SHA，留空使用 Git 默认 HEAD。Codeup 仓库列表没有提供默认分支字段，因此不会假设为 `main` 或 `master`。
5. 在受支持的执行器上运行后，检查拉取的提交 SHA 与预期一致。当前 Actions 执行器需要 Linux 或 macOS；Codeup 连接本身不依赖执行器操作系统。

连接和凭据支持独立复用、修改与轮换。替换凭据后刷新仓库/分支并重新执行验证；已有流水线继续引用连接 ID，不需要把令牌写进 YAML。删除正在被引用的凭据会被阻止。

401 表示令牌无效或过期；403 应检查令牌授权范围及账号仓库权限；404 应检查组织 ID、仓库可见性和接入点；429 表示限流，可稍后重试。服务错误、异常 JSON 和错误列表结构均会明确报错。不会跟随 API 重定向发送令牌，也不会把上游错误正文中的凭据回显。

接口依据：[服务接入点](https://help.aliyun.com/zh/yunxiao/developer-reference/service-access-point-domain)、[仓库列表](https://help.aliyun.com/zh/yunxiao/developer-reference/listrepositories-query-code-base-list)、[分支列表](https://help.aliyun.com/zh/yunxiao/developer-reference/listbranches-query-the-list-of-branches)。使用新版 `x-yunxiao-token` PAT 接口，不使用旧版 AccessKey 签名 API。分支查询中的仓库完整路径只编码一次，保留组织/分组层级及中文、空格等字符。

市场来源的 API 主机必须与仓库主机一致，官方例外为 GitHub 的 `api.github.com` 和 Codeup 的 `openapi-rdc.aliyuncs.com`。不会通过重定向转发认证信息。

## 仓库列表与监控通知

连接详情包含“基本信息 / 仓库列表 / 监控通知”。仓库列表可切换列表和分组模式；分组按完整组织/命名空间展开、收起，数量仅统计当前页，不会为了分组自动读取全部远端仓库。

在“监控通知”中配置全部仓库或指定仓库完整路径（每行一个），选择推送、分支、标签、PR/合并请求以及平台支持的仓库新增/删除事件。配置属于当前授权用户的连接，并沿用工作空间仓库权限。普通 Git 连接不提供平台事件。

监控类型可选择“事件推送”或“主动轮询”，旧配置保持事件推送模式。

事件推送：保存 Webhook 验证密钥后，在代码平台手动配置 JSON Webhook，接收地址为公开服务地址加页面显示的 `/api/repository-events/{连接ID}`。本机回环地址不能被云平台访问；反向代理须允许该回调路径。验证密钥和通知 Webhook 地址加密存储，详情只显示是否已设置，编辑留空保留原值。更换密钥后旧密钥立即失效。

主动轮询：间隔以整数分钟配置，默认及最短为 **1 分钟**。复用当前连接凭据，需要连接所有者具有仓库与凭据读取权限，远端凭据也应具有所选资源的读取权限。无需接收地址或验证密钥，启用后不接收事件推送回调。服务读取完整分页，比较仓库可见列表、分支提交、标签以及 PR/合并请求的元数据变化。首次成功检查只建立基线，保存配置后重新建立基线，不补录过去事件。检查失败不替换基线、不推断删除，错误可在详情查看。

轮询基线加密持久化到业务数据库，重启后继续比较；多服务副本通过共享数据库事务与可续期租约领取任务，配置版本或连接归属改变后的旧结果不能写入。轮询只能发现两次成功检查间可观察到的变化：期间发生又撤销的操作可能遗漏，仓库不可见可能表示删除或访问权限变化。轮询通知复用下方相同的一次性投递机制。

| 平台 | 回调认证 | 事件范围注意事项 |
| --- | --- | --- |
| GitHub | `X-Hub-Signature-256` 的 HMAC SHA256 签名 | 仓库新增/删除需要组织级事件 |
| GitLab | `X-Gitlab-Token` | 仓库新增/删除需要实例支持的系统级事件 |
| Gitea | `X-Gitea-Signature` 的 HMAC SHA256 签名 | 依实例 Webhook 支持范围配置 |
| Gitee | 密码模式 `X-Gitee-Token` | 不支持签名模式的替代认证 |
| Codeup | `X-Codeup-Token`，事件头 `Codeup-Event` | 支持推送、标签、合并请求；仓库 Webhook 不提供仓库新增/删除 |

事件推送模式下，Codeup 的“全部仓库”表示接收端不过滤仓库，仍需在各仓库配置 Webhook。参考 [Codeup 官方 Webhook 设置](https://help.aliyun.com/zh/yunxiao/user-guide/webhooks-settings)。推送模式不会通过仓库不可见等间接变化推断删除事件。事件以实际收到的回调为准，未配置回调前不会出现记录，也不会补录之前的历史。主动轮询模式可检测凭据可见仓库的新增或移除，并明确标注其可见性语义。

### 事件明细

事件记录列出摘要（合并请求标题、最新提交说明或标签说明）、操作人和通知结果；点击一行查看完整明细：

| 事件 | 明细 |
| --- | --- |
| 代码推送 | 推送前后版本、提交数、是否强制推送、对比链接，以及每个提交的 SHA、完整提交说明、作者、时间和链接（最多 20 条，超出时注明） |
| 新增分支 / 标签 | 指向的提交及其说明和作者，标签说明与创建人 |
| 删除分支 / 标签 | 删除前指向的版本 |
| PR / 合并请求 | 编号、标题、完整说明、状态、源与目标分支、作者、合并人、评审人、合并提交、各时间点和链接 |
| 新增仓库 | 可见性、默认分支、描述和地址 |

操作人：事件推送使用平台回调中的推送、合并或删除账号。主动轮询只填写平台明确给出的账号：新增 PR 为作者，合并为合并人，附注标签为标注人；推送、新增或删除分支等无法确认实际操作账号的事件不填写操作人，也不附加说明。提交的作者单独列在每条提交中，不作为操作人。提交作者的邮箱不会保存。

### 通知

通知地址可留空，此时仅记录事件。以下官方机器人地址会按平台格式发送可读消息（事件、仓库、分支、操作人、提交或合并请求摘要和链接），并以平台返回的结果码判断是否成功；其中部分平台拒收时仍返回 HTTP 200，失败原因会显示在通知结果中：

| 平台 | 地址格式 |
| --- | --- |
| 企业微信群机器人 | `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=…` |
| 钉钉群机器人 | `https://oapi.dingtalk.com/robot/send?access_token=…` |
| 飞书 / Lark 群机器人 | `https://open.feishu.cn/open-apis/bot/v2/hook/…`、`https://open.larksuite.com/open-apis/bot/v2/hook/…` |
| Telegram 机器人 | `https://api.telegram.org/bot<令牌>/sendMessage?chat_id=<会话ID>` |
| Slack Incoming Webhook | `https://hooks.slack.com/services/…` |
| Discord Webhook | `https://discord.com/api/webhooks/…` |
| Google Chat 空间 Webhook | `https://chat.googleapis.com/v1/spaces/…/messages?key=…&token=…` |

需要加签或关键词校验的机器人未做特殊处理，平台拒收原因会显示在通知结果中。WhatsApp 需要访问令牌、接收号码和平台审核的消息模板，暂不支持。其他 HTTP(S) 地址接收包含事件、仓库、分支/标签、操作人、连接标识和事件明细的 JSON；不转发令牌或原始事件正文。报警通知使用相同的地址识别规则。

每次接收先在共享数据库去重并记录，再尝试一次通知；不跟随重定向，10 秒超时，失败可在事件列表查看。不会自动重试，服务在投递期间中断可能留下未完成的投递记录。重复相同认证正文不会重复通知，多服务副本共用数据库即可共享去重状态。

### 保留时间

“维护 → 配置项”的“仓库事件保留天数”控制事件记录保存多久（例如 7、30、365；0 为永久，默认永久）。服务每 10 分钟按工作空间清理超期记录，清理写入操作审计。

## 市场索引

在外部仓库提交 JSON 文件，例如 `marketplace.json`：

```json
{
  "version": 1,
  "templates": [
    {
      "key": "web",
      "name": "Web 示例",
      "description": "单服务示例",
      "content": {
        "apiVersion": "ferry/v1",
        "kind": "Application",
        "metadata": { "name": "web" },
        "services": [{ "name": "web", "image": "nginx:stable" }]
      },
      "parameters": []
    }
  ]
}
```

在“市场来源”选择仓库，设置提供方、API 接入点、项目路径、分支及索引路径。GitHub/Gitee 使用 `owner/repository`；GitLab 可使用项目路径或项目 ID；Codeup 填写仓库 ID 和组织 ID，API 接入点为 `https://openapi-rdc.aliyuncs.com`。

点击“立即同步”后才更新目录。索引最多 500 项，解码后最多 2 MiB；全部模板校验成功后原子替换目录，失败保留上次成功内容并显示错误。定时同步在共享定时任务中选择部署范围、市场来源及同步动作。

在“应用市场”查看模板并导入，得到独立的应用模板。后续来源同步不会覆盖已导入模板，导入也不会自动部署。

## 验证范围

当前已用隔离 HTTP 提供方及 Chromium 验证授权、令牌续期、市场同步和导入流程；另用受认证保护的真实 Git 仓库验证五个平台连接选择后在 Runner/SSH 上拉取、执行仓库内脚本及产物归档，并用浏览器验证构建表单到实际 Runner 构建。真实第三方账号、组织权限策略以及安装版 WebView 的授权兼容性尚未验收；接入真实部署后需使用实际测试仓库完成授权、私有文件读取和重新授权验证。
