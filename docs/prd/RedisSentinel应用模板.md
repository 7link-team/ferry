# Redis Sentinel 应用模板

## 范围与事实依据

本期将《应用高可用拓扑与多部署驱动方案》§11.5 的 Sentinel 场景接入既有应用模板、配置模板及 SSH/HostAgent 部署链路。项目依据为 `scripts/test-ha-topologies.py::redis_sentinel` 的固定镜像与协议实验、`deployments/manifest.rs` 的 v2/overrides/卷/配置文件契约、`templates.rs::seed_examples` 的新空间事务初始化。旧协议实验不作为本模板的驱动准入证据。

一份应用包含三个单副本 Redis 和三个单副本 Sentinel，六份独立持久卷。初始 Redis A 为主，B/C 为副本；三个 Sentinel 以相同逻辑名 `example` 监控，quorum=2。运行后的主角色由 Sentinel 决定，不能按初始角色覆盖运行配置。Compose 是单机进程冗余；Stack 要求三个不同节点预设 `ferry-redis=a/b/c` 标签，每节点放置一个数据成员与一个 Sentinel，各自的卷不跨机迁移。

不新增调度器、数据模型、Redis Cluster、TLS、ACL角色管理、跨机卷迁移、备份恢复、全停自动引导或协议监控页面。Sentinel 异步复制不承诺 RPO=0；失去 Sentinel 仲裁不代表当前 Redis 主库禁止写入。本示例以 `min-replicas-to-write=1`、`min-replicas-max-lag=10` 限制孤立主库写入，不作为所有网络分区下的强隔离承诺。

## 配置与流程

| 字段 | 类型 / 必填 / 默认 / 限制 | 来源与作用 |
|---|---|---|
| password | string，必填，无默认，既有变量名规则 | 引用本空间 deploy 密钥变量；数据、复制与 Sentinel 使用同一密钥，模板不存明文 |
| startup | string，默认 example-redis-start，1～60字符 | 当前空间启动脚本配置模板名称或ID |
| ip_a/b/c | string，必填，无默认，7～15字符 | 对应主机的可达IPv4；启动脚本拒绝非数字/点，Redis验证地址；成员和客户端均须能访问，禁止填127.0.0.1或0.0.0.0 |
| data_port_a/b/c | integer，默认6379/6380/6381，1～65535 | 数据端口，同时作为监听、发布及通告端口，禁止NAT端口重映射 |
| sentinel_port_a/b/c | integer，默认26379/26380/26381，1～65535 | Sentinel端口，同时作为监听、发布及通告端口 |

所有六个端口在目标网络内保持唯一。每个节点IP可以不同；Compose三组IP为同一宿主的可达地址。Stack使用主机IPv4和路由网格，发布端口与监听端口相同；不依赖容器IP、服务VIP或固定主角色DNS。客户端使用支持Sentinel的库连接三个独立Sentinel入口，逻辑主名为 `example`，并为Sentinel及数据连接配置同一密码。运行集群的地址/端口变更需要同步重配成员、Sentinel与客户端，不承诺修改模板参数即可在线迁移；既有卷不按新初始地址重置。

启动脚本只在该卷的配置不存在时创建初始配置，随后复用可写的 `/data/redis.conf` 或 `/data/sentinel.conf`。Sentinel的自动重写与Redis的CONFIG REWRITE持久保存选主/复制状态；重启、重部署不复制初始配置覆盖它们。认证和通告参数在启动时通过Redis原生参数设置，配置重写后含密钥的运行文件位于各自卷中，须按敏感持久数据保护；平台密钥仍沿用既有加密存储。密码轮换要求六成员协同操作，不声明在线无中断轮换。

数据成员开启AOF，每秒刷盘；数据成员512Mi限制、Sentinel128Mi限制。使用既有Compose/Stack overrides配置原生 `redis-cli PING` 健康检查，使用环境变量认证且不打印密钥。健康只表示对应进程可达，不表示选主/复制/仲裁健康；协议验收单独检查这些事实。没有HTTP探针，不伪造HTTP成功。

流程为创建空间→创建deploy密钥变量→选择模板→填写端点/标签/主机/模式→生成→保存→预览确认→部署。初始化和渲染不执行；原空间不回填；删除模板不重建。配置缺失、空间外引用、权限不足、无标签/不可达/冲突/认证失败沿用现有错误链路，失败不标成功。删除应用保留卷，使用者不得把旧卷用于不同逻辑集群。
