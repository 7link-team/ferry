# 应用高可用拓扑与多部署驱动方案

状态：方案/实验阶段，不代表表内服务已实现产品兼容。用户补充范围：PXC、Redis Sentinel、NATS、Nginx、XXL-JOB、Ferry 多活；不得把所有 HA 等同于 Swarm 副本。

## 1. 分层与复用

项目依据：主方案“服务拓扑模板/可移植应用定义/目标驱动”三层边界；现有 v2 Application、Native/Docker/Compose/Stack 渲染、host-group 每目标计划和历史快照；Ferry 启动配置、NATS transport、SQL 租约/worker ID、文件存储。PXC 的专用协议与实验见《PXC三节点部署与恢复方案》。本文件扩充共同契约，不替换该实验。

| 层 | 责任 | 禁止混用 |
|---|---|---|
| 拓扑蓝图 | 服务角色、身份、依赖、复制/仲裁、初始成员、入口、恢复/升级步骤 | 不等同于容器 replicas |
| 寻址与发现 | 监听、成员互连、客户端入口、通告、发现方式和DNS/IP绑定 | 不把 0.0.0.0、容器临时IP、代理VIP直接当节点身份 |
| 存储 | 数据身份、卷/目录、故障域、备份、隔离和重建 | 本地卷重建不等于迁移原数据 |
| 部署驱动 | Native、Docker、Compose、Swarm 的渲染、执行、状态读取 | 不把原生主机部署假装具备Swarm调度 |
| 运维流程 | 首次初始化、扩缩容、故障恢复、更新回滚、审计/审批和单一执行所有者 | 不用一个“重启全部”覆盖所有服务 |

同一个应用蓝图按驱动生成目标计划。复用现有 `ferry/v2 Application` 作为每目标执行产物；跨主机角色编排、端点绑定和服务适配器目前没有产品模型，不擅自往v2加字段或宣称已注册。产品数据模型/API、迁移up/down在接入开发前补齐；本轮无产品数据库变更。

## 2. 服务目录：同一基座，不同协议适配器

以下数量是首批实验拓扑，不是所有生产环境的固定上限。外部协议仅指导适配器设计；实际产品字段以项目设计/实现验收为准。

| 蓝图 | 拓扑与身份 | 健康/入口/恢复契约 | 当前状态 |
|---|---|---|---|
| PXC | 三独立数据成员，多写复制；独立卷与故障域 | Primary/Synced/ready；唯一bootstrap；SST/IST；全停候选评估与隔离 | 8.0/8.4隔离故障实验通过；全停自动恢复未验证，未产品接入 |
| Redis Sentinel | 一个当前主、两个副本、三个Sentinel；主角色可变，成员身份稳定 | Sentinel仲裁/选主、客户端支持Sentinel发现；复制偏移/延迟；旧主归队必须成为副本 | 隔离协议实验通过，产品接入未完成；不能当Redis Cluster |
| Redis Cluster | 分片主节点及各自副本、槽位与集群总线 | 槽位完整、重定向、分片故障转移、扩缩容迁槽；客户端必须支持Cluster | 独立蓝图，不能复用Sentinel初始化脚本冒充兼容 |
| TiDB | SQL层TiDB、元数据/调度PD、持久化TiKV分别定义成员和故障域 | 分别验证SQL入口、PD仲裁、TiKV区域副本与调度；成员发现和客户端SQL入口分开；扩缩容须等待数据迁移 | 保留用户前述范围，未实现/未实测；不能用MySQL协议连通或NATS仲裁测试代替 |
| NATS Core | 多个活跃服务器，路由/客户端发现 | 路由完整、客户端重连、订阅恢复；不承诺持久消息恢复 | 和JetStream分开验收 |
| NATS JetStream | 多服务器，流/KV的复制与仲裁分别配置，独立store | leader切换、复制组、持久消息与consumer恢复；副本数不能超过可用节点 | 流复制/leader及持久consumer恢复实验通过，Ferry集成另验 |
| Nginx | 无状态多副本，一致配置；上游有独立健康条件 | 配置校验后原子reload；上游失败切换；两个Nginx不自动产生一个HA入口 | 上游失败切换隔离实验通过；VIP/LB/外部DNS另验 |
| XXL-JOB | 多admin共享数据库、调度协调；executor应用与实例分组 | admin登录/API可用不代表调度接管；验证同一触发不重复、故障后的调度和日志归属；executor自身幂等 | 新适配器待验证，不承诺Exactly Once |
| Ferry | 多服务实例、共享SQL/主密钥/命名空间、独立实例ID/目录、NATS和共享文件存储 | API/WS/Agent跨实例、执行租约/栅栏、worker ID不冲突、单实例退出恢复、依赖失败关闭 | 有代码与既有集群回归；整套依赖HA不因此自动完成 |

模板先使用现有应用模板/参数与凭据概念，不新增“数据库集群管理”等平行一级模块。类型差异由模板角色与能力展开；用户仍操作同一个应用的部署、监控、版本与恢复入口。

## 3. 寻址矩阵

| 驱动/目标 | 成员发现 | 客户端入口 | 编译前必须检查 |
|---|---|---|---|
| 单机Native | 已绑定且本机可解析的主机名/IP及实际端口 | 主机端口/已有入口 | 端口冲突、目录权限；不能仅靠三个进程声称跨主机HA |
| 多机Native | 每角色绑定SSH/Agent目标的私网IP或可解析DNS | 外部LB/VIP/DNS或协议客户端发现 | 跨机可达、明确故障域、每目标配置不同、host-group不是盲目复制相同成员身份 |
| 单机Docker/Compose | 同一用户网络的服务名；跨网络需显式可达地址 | 发布端口/代理 | Compose项目间DNS隔离；容器端口不等于主机映射端口；不能拿内部别名通告给外部客户端 |
| 跨机独立Docker | 私网DNS/IP和固定可达端口；没有内置跨机服务DNS | 外部入口或协议客户端发现 | NAT、端口、防火墙、TLS名称，不能拼接Compose服务名 |
| Swarm | 应用需要负载入口时使用服务VIP；需要成员身份/复制互连时用DNSRR/任务发现或稳定绑定 | published端口/代理/外部LB | VIP与成员地址语义、endpoint_mode、成员启动次序、任务IP变化、卷归属与容量 |

必须分别建模：

- 监听地址：进程在哪个接口接受连接；`0.0.0.0`只能用于监听。
- 成员地址：复制、路由、仲裁的peer端点；可由可验证的发现机制生成。
- 通告地址：服务返回给其他节点或客户端的地址；接收者必须能访问。Redis的data/replica/Sentinel通告分开，NATS的client/cluster路由分开。
- 客户端地址：业务使用的入口/发现清单；数据库多主不等于客户端只需轮询任意节点。
- 运行身份：与DNS/IP解耦；换IP不等于新成员，换卷/身份需进入替换流程。

IP和主机名均支持显式绑定；IPv6使用方括号端口格式并单独验证。自动检测仅提供建议值，用户确认后写入部署快照。地址无法证明可达或服务不支持当前NAT通告方式时，编译结果为“禁止”，不能静默回退localhost或临时容器IP。

地址绑定按服务能力判断，不能只做“DNS/IP”通用开关。Sentinel使用主机名时需核对当前Redis版本的 `resolve-hostnames` / `announce-hostnames` 与客户端支持；本轮实验只使用可达私网IP。NATS对外通告不能把内网容器地址直接返回给外网客户端。Nginx开源版本本轮验证的是请求失败后的被动摘除，不冒充已部署主动HTTP健康检查控制器。

## 4. 配置生成、漂移与生命周期

蓝图保存逻辑角色与引用；目标绑定保存每角色的主机/网络/目录/端口；适配器生成成员配置、环境、启动命令、就绪和恢复步骤。首领/主节点等动态角色由服务协议决定，不能永久写死“最初a就是主”。动态发现结果不能覆盖用户原始蓝图。

部署预览展示每目标配置差异、成员端点、卷身份、凭据引用、启动顺序、需要的仲裁和失败条件。保存、校验、预览、执行分别记录；配置渲染成功不代表目标能力或数据库健康通过。状态依据带时间戳的实时观测，保留未知/过期/部分失败。

生命周期按适配器定义：校验目标→预备目录/网络→首次初始化或加入→协议就绪→开放入口→监控；故障→摘流→确认故障域与隔离→重启/归队/替换→同步→接流量。全停恢复、主从切换、移除成员、删卷、重分片分别预览与授权，不能共享一个默认脚本。

同一操作只有一个持租约的执行者；SQL租约和远端执行栅栏复用现有执行系统。Swarm接管的任务由Swarm恢复，Native/独立Docker的服务级自动替换在适配器与fencing未完成前不提供；显示“人工恢复”，不能伪称自动调度。

## 5. Ferry自身多活的依赖契约

已有代码：`main.rs` 在配置NATS集群模式时要求共享数据库URL与共享主密钥；`cluster.rs` 使用Core NATS传递实时流、JetStream KV维护有时效的连接归属；worker ID和执行租约有现有SQL协调。`README` 要求各实例独立数据目录与实例身份，反向代理支持WebSocket，共享文件存储。

部署模板必须绑定：共享PostgreSQL/MySQL的可用入口、相同主密钥与命名空间、独立实例ID/目录、满足副本数的NATS JetStream、S3/经验证共享文件存储、支持WS的外部入口。不能把SQLite文件放网络盘当集群SQL；本机文件模式不能直接扩成多机共享。Redis当前配置/监控不是所有多活功能的必选依赖，也不能以“起了Redis”替代SQL/NATS协调。

验收拆开：Ferry实例失败、数据库主入口切换、NATS leader/路由失败、S3暂时不可用、Agent重连、活跃执行所有权接管、worker槽位回收、版本不一致升级。已有某一项PASS不能推出整套依赖HA已认证。现有`test-cluster.mjs`与Rust集群回归复用，另补完整依赖故障矩阵；旧CI只标历史证据，不冒充新方案端到端复验。

## 8. 各角色配置与恢复的具体区别

本节为后续适配器的执行契约，不是当前已经可提交的 Application 字段。配置键为相应服务的原生配置；蓝图到产品模型的映射在接入时评审。

| 蓝图 | 每个角色的配置差异 | 谁负责选主/恢复 | 必须拦截的操作 |
|---|---|---|---|
| PXC | 每成员独立 `wsrep_node_name/address`、目录和对等端点；唯一首次引导者，常态均配置加入地址 | Galera负责成员仲裁/复制；驱动负责进程存活；适配器负责安全加入与人工恢复计划 | 无隔离证明的重复bootstrap；丢卷成员以旧数据身份直接接流量；同步前加入可写入口 |
| Redis Sentinel | 数据成员持久目录与复制/通告地址各自绑定；Sentinel配置同一master逻辑名和可达端点，各自保存动态状态 | Sentinel仲裁选主和重配复制；驱动不能同时按初始配置强制旧主恢复主角色 | 每次重启覆盖Sentinel运行配置；将主节点固定DNS直接当永久写入口；以Sentinel切换承诺零丢失 |
| NATS JetStream | 每server独立server name/store目录，cluster name和routes一致；监听与client/cluster advertise分开；每stream/KV另设replicas | NATS选leader与追平；驱动重启实例；适配器验证复制组恢复 | 三server但stream replicas=1便宣称持久数据HA；复用同一store；无仲裁时强行删旧组重建 |
| Nginx | 多前端共享配置版本；各目标监听端点可不同；上游列表与健康策略来自被代理服务；外部入口另绑定 | Nginx负责请求级上游失败切换；驱动负责进程；外部LB/VIP负责前端故障切换 | 无 `nginx -t` 就reload；把失败后的写请求无条件重试并承诺无副作用；未提供入口仍显示端到端HA |
| XXL-JOB | 多admin共享同一数据库和兼容版本；executor设置应用组、实例地址、回调可达的通告地址与访问凭据 | XXL-JOB负责调度协调；executor业务负责幂等；驱动仅恢复进程 | 只用HTTP 200认证调度HA；重启admin即补发全部历史任务；以多admin承诺Exactly Once |
| Ferry | 各实例独立ID/目录、同一SQL/主密钥/namespace、NATS端点、共享文件与WebSocket入口 | 现有SQL租约/栅栏和NATS路由负责执行协调；部署驱动恢复服务进程 | 多机共享SQLite文件；同实例身份/目录；默认本机文件存储直接扩多机；绕过执行所有权接管任务 |

拓扑、协议角色和进程副本分别显示。例如“三台Redis + 三台Sentinel”与“Redis Cluster三主三从”是两个蓝图；“三个NATS server”与“一个stream三副本”是两层设置。失联、降级、不可写、同步中均不能折叠成同一个“运行中”。

网络分区须另验：Sentinel失去仲裁禁止再次选主，不表示旧主所在分区必然无法接受写入；客户端发现、旧主隔离和复制写入约束共同评估。PXC多写存在事务冲突，客户端重试必须有业务幂等策略。自动重启、协议故障转移、空卷重建、跨机迁移是四种不同操作，分别显示能力与证据。

驱动执行的差异也固定保留：Native生成每目标的程序/服务配置和目录，使用目标已支持的进程管理能力；Docker生成每主机的独立容器及固定可达端点；Compose仅在同一Docker主机生成项目网络与服务；跨机不把多个Compose项目拼成一个网络。Stack交给Swarm分配任务，成员身份/放置/卷约束仍由蓝图限定。任何驱动都不得因为缺少隔离、发现或存储能力，静默改为三份相同配置。

### 10.1 配置编译与预检

1. 服务适配器声明角色、成员身份、端点用途、协议探针、数据持久化与生命周期。驱动提供发现、进程管理、放置、网络和卷能力，两者分别校验。
2. 每个端点同时记录使用者范围：成员、同网络客户端、跨网络客户端或外部入口。以使用者所在目标发起解析与连通性预检；Ferry服务器能连接不替代目标主机能连接。
3. 配置预览列出每角色的目标、监听、互连、通告、业务入口和数据位置。成员名、端口、目录及通告缺失或冲突时阻断；不得静默套用相同成员配置。
4. 服务名可寻址不等于可以负载均衡；需要具体成员的复制、仲裁、executor回调必须解析到符合协议的成员。地址变化时按该服务的重新发现/重配置流程执行，不能只更新一份环境变量。
5. 已有运行集群与全新集群分开处理；发现已有数据、已有成员或身份冲突后禁止首次初始化。接管存量集群另立授权及验收，不由“部署”隐式执行。
6. 凭据复用现有空间凭据引用；配置和日志脱敏，预检与执行均复核空间/对象授权。正式持久化字段、API和DDL仍按第7节在产品接入前定义，本节不新增数据库模型。

### 10.2 自动化能力分级与验收

同一部署分别展示进程重启、协议故障转移、成员重建、跨主机迁移的能力与测试结果，不合并为“自动恢复”开关。服务已能在剩余成员继续运行，不代表已恢复原有冗余；没有备用容量、隔离证明或可恢复数据源时，成员替换保持阻断并展示原因。

| 层次 | 契约 | 当前依据与缺口 |
|---|---|---|
| 声明式 YAML | 服务/角色、参数、变量与密钥引用、配套文件、依赖、端口、拓扑、健康条件属于统一部署规范；文件保留原生格式 | 当前已有 ferry/v1/v2、blueprint-v1 与 deploy-v1；统一概念不能直接删除这些版本及其兼容链路；具体统一字段与版本映射待补 |
| 类型化表单 | 输入框、数值、枚举、密钥引用、文件、节点绑定使用对应控件；表单与 YAML 双向操作同一配置，保留类型、层级和未修改字段；结构编辑覆盖对象/数组增删、排序及引用检查 | 普通 ManifestEditor 支持服务编辑；蓝图 ApplicationTemplateEditor 当前仅只读字段预览和 YAML 编辑；不具备完整结构编辑能力 |
| 拓扑可视化 | 投影节点承载服务、实例角色、依赖、连接方向及端口；叠加部署进度和实际健康；点击对象定位配置或执行详情 | BlueprintTopology 已有角色/实例/主机和实例健康汇总，尚无完整关系画布与源→目标端口健康记录 |

文件参数不仅是一个不同控件：还需保留文件内容或引用、目标路径、文件参数和已有权限/挂载语义；密钥通过授权引用读取。具体字段沿用现有模型或进入详细设计，禁止假定三者都是可任意展示的字符串。

### 14.2 共享页面组件的三种业务模式

| 模式 | 内容与操作 | 约束 |
|---|---|---|
| 市场包 | 共享定义/表单预览/配套文件/拓扑组件；导入模板或进入部署向导 | 只读；内容由市场仓库提交与同步产生；不在详情页直接改包 |
| 工作空间模板 | 同一配置组件允许定制定义、参数和配套文件；用于部署、导出市场包 | 遵守空间与既有模板权限；版本与依赖一并管理 |
| 部署实例 | 同一配置组件展示所用定义和版本，填写目标绑定与参数；执行、查看健康/日志/拓扑，保存为模板或导出 | 运行时状态、执行记录与可复用定义分离；运行中操作受已有状态机约束 |

同一个模板可生成开发、测试、生产等多套独立部署。每套保留自己的定义版本、参数、密钥引用、节点绑定与执行记录。模板修改不隐式修改运行实例；某套部署升级时显式选版本、检查差异并执行。环境命名与分组是否新增字段尚待评审，不将开发/测试/生产硬编码为仅有选项。

### 14.3 完整包的流转

市场包→工作空间模板→部署实例；市场“部署”可复用导入及部署向导链路。模板→市场仓库包；部署配置→模板或市场仓库包。

每次转换必须处理定义、参数、配套文件与引用、元信息及版本来源。现有 schemaVersion2 已承载 blueprint/parameters/files/meta/readme，优先复用，不创建第二套包格式。当前 catalog::install 事务导入配置文件并处理名称冲突、重写 fromTemplate，属于已实现正向链路；反向导出尚未实现。通用资源列表 JSON 导出不满足市场包导出契约。

部署导出需显式确定如何将具体参数值、主机绑定转换为可复用参数，以及如何保留密钥引用而不发布密钥明文；缺失依赖、包版本冲突、未授权引用均需定义阻断规则。导出到本地文件和向远程市场仓库提交分开；不自动推送、覆盖或发布。

### 14.7 推荐统一边界：包定义、实例绑定、运行观测

此节为待评审设计建议，尚未修改协议。采用同一份声明模型驱动YAML、表单和图，保留三类数据的责任边界：

1. **可复用包**：复用市场v2结构，选定一个包版本作为编辑根，包含完整blueprint、parameters、files、readme及meta；市场展示只读，模板展示可编辑。工作空间模板的当前行是兼容旧接口的投影，不能成为遗漏文件或版本来源的第二份事实源。
2. **部署绑定**：引用包的不可变版本，保存用户输入、变量/密钥引用、驱动、角色数量及目标。沿用DeploySpec等既有执行类型，通过适配器进入现有预检/编译器。开发/测试/生产是用户创建的独立实例，不硬编码为三个环境或由名称推断权限。
3. **运行观测**：部署修订、目标执行状态、实例健康和链路探测结果。只叠加到图与运行详情，不反向写入可复用定义。

“一套YAML”指统一作者入口和一致的定义契约，不把所有运行日志、实际密钥和探测结果写回配置。保存与执行为两个动作；保存草稿不部署，切换表示不保存或部署，图上选择对象不触发远程操作。

推荐作者入口复用schemaVersion2完整包的YAML表示；仓库索引继续兼容现有JSON表示，两者解析后为同一字段结构。当前仓库入口的文件名、允许的YAML标记、重复键及大小/别名限制必须在实现前给出协议兼容测试；不以改扩展名代替解析器适配。现有Application/Blueprint/DeploySpec保持可读，禁止强制迁移历史数据。

### 14.8 版本与文件的完整快照

推荐复用definition_revisions存放不可变包版本，新增受控的模板种类与读取授权，不新建平行“版本中心”。现有subject_kind长度16可容纳模板种类，但具体种类值、读取API及写入编号策略仍需接口评审。

| 对象 | 当前版本含义 | 推荐规则与阻断条件 |
|---|---|---|
| 市场条目version | 目录并发更新计数 | 导入前校验；变化则重新获取并让用户确认，不能自动换包 |
| package_version | 仓库包的语义版本字符串 | 与内容digest、来源key一起展示；本地保存次数不能冒充发布版本 |
| app/config template.version | 可变行的乐观锁计数 | 保留并发写校验；不可变包编号与该计数的映射必须明确，不直接混用 |
| definition revision.number | 当前按对象递增的不可变定义编号 | 模板接入后固定全包、文件内容及参数；存在版本读取后不能回退为读最新行 |
| deployment.version | 部署配置并发令牌 | 预览及执行仍校验，避免他人修改后执行旧计划 |
| deployment revision.number/id | 一次执行/回滚的证据 | 与定义版本分别标注；回滚执行证据不自动覆盖模板当前版本 |

快照必须含所有引用文件的实际内容与参数、原始引用对应关系和来源；保存包版本时原子读取依赖并计算摘要。文件模板单独更新后，旧包版本继续使用旧快照。新包版本需显式更新依赖，显示差异。导入名称冲突后的fromTemplate重写只作用于本次导入的完整包，不能改其他包。

源YAML与规范化语义需分别用于编辑保真和一致性验证。现有definition字段存JSON且record按语义去重，直接复用会丢失作者注释：推荐按模板种类扩展源文本处理，保留作者YAML，独立计算语义摘要；普通pipeline/workflow/agent/model不改行为。源文本存储方式、无内容变化/仅注释变化的版本规则以及原子更新方案为明确待评审项，不能用UI缓存冒充跨刷新保存。

历史处理：只能为当前可读取模板和依赖建立基线快照，禁止合成不存在的旧版本。已有执行记录保留；缺失原模板/文件来源时显示“历史定义不完整”，允许查看既有执行证据，不显示可完整重建或可完整导出。回填是否写现有definition表及回滚/降级清理范围，需提交up/down说明；本PRD不授权执行回填。无新增表/列的方案不提供虚构DDL；任何新增模型须另补字段约束、审计与逐字派生DDL后评审。

### 14.9 一套表单的模式与编辑契约

| 区域 | 市场 | 模板 | 部署 |
|---|---|---|---|
| 定义/源YAML | 固定目录版本，只读 | 完整结构编辑及源编辑 | 显示绑定的源版本；具体绑定单独编辑，不篡改公共模板 |
| 参数定义/填写 | 看定义并临时试填，试填值不写市场 | 编辑参数定义/默认值 | 按类型填实例值；缺必填项拦截预览与执行 |
| 配套文件 | 看文件名、内容、参数、引用路径 | 编辑内容/参数并维护引用 | 展示选定版本文件及本实例渲染预览；密钥继续脱敏 |
| 目标/拓扑 | 计划角色图；未绑定主机不显示真实节点 | 编辑结构与约束，查看计划图 | 主机/实例实图、状态、日志、事件和探测证据 |
| 主操作 | 导入模板、进入部署向导 | 保存版本、创建部署、导出包 | 保存配置、预览、执行、回滚、保存为模板/导出；均按权限与状态可用 |

共用结构编辑器通过只读模式与操作配置复用，不复制三套表单。普通标量使用现有类型控件；数组提供增删/排序，映射提供键管理；添加仅允许当前schema字段，字段与排序不会被空值自动清掉。姓名/服务名等稳定标识变更需同步引用或阻断；删除被引用服务/文件/端口前列出引用位置，用户修复后才能保存。dependsOn环及缺引用由已有后端校验兜底。

表单→YAML采用文档节点增量修改，保留未触及字段、模板表达式及注释；不能通过“重建所有已知字段”丢掉新版本属性。YAML错误时保留原文与错误路径，不进入可编辑表单；修复后再切换。未知或当前不支持的字段原样保留并明确标为源编辑范围，后端不支持则不能保存/执行；不伪装完全可视化支持。切换图、表单和源不会丢草稿；保存前展示版本冲突，禁止自动覆盖。

文件选择器第一阶段只能使用已有string参数和fromTemplate语义；不能在旧Parameter协议里新增file/object类型而不升级校验。全包文件内容、目的路径、引用、变量/密钥读取权限分别保留。普通值中的false、0、空串、缺省和null按现有字段语义处理，禁止用真假判断将它们合并。

### 14.10 转换闭环与失败行为

| 编号/转换 | 输入版本与操作 | 输出/原子性 | 拒绝条件 |
|---|---|---|---|
| C01 市场→模板 | 用户选包及版本，检查目录version和兼容性 | 复用install事务，模板、文件及引用一起成功；保留来源 | 无配置模板创建权、包变更、不兼容、缺文件或重写失败；全回滚 |
| C02 市场→部署 | 固定包版本后进入现有导入与部署向导 | 导入完成后显示模板来源、填写绑定；另行保存及预览执行 | 无部署创建权时只能导入；取消向导不删除用户已导入模板，也不创建远程资源 |
| C03 模板→部署 | 固定不可变全包版本；填写值和目标 | 新部署拥有独立ID、绑定、参数和后续执行历史 | 版本不存在、引用越权、缺必填、驱动不支持、放置冲突；不改模板 |
| C04 部署→模板 | 选明确的已保存配置/修订来源，查看去实例化差异 | 新建空间模板，默认不覆盖已有模板；依赖完整快照 | 不能恢复源定义、依赖缺失、试图导出明文密钥；不从rendered反编译并冒充源定义 |
| C05 模板→市场包 | 选模板版本，补package key、发布版本和meta；查看完整包 | 生成本地可验证的市场v2包；同名现存文件不静默覆盖 | 未授权文件、依赖不完整、元信息/版本非法、表达式不兼容 |
| C06 部署→市场包 | 复用C04去实例化与C05打包 | 显式确认参数化/剔除绑定后的包；不带运行观测 | 与C04/C05相同；未解决绑定或密钥引用则阻断 |
| C07 本地包→仓库 | 用户选择目标仓库/路径，审阅差异后提交 | 复用仓库授权与审计；独立于本地导出 | 无仓库写权限、分支冲突或提交失败；不自动发布/合并，不新增一键强推 |
| C08 包→再导入 | 用完整包解析器与相同版本执行校验 | 保持语义、类型、文件内容和引用一致；本地ID/合法冲突后名称可变 | 文件摘要、参数或引用丢失则验收失败，不能只对比显示名称 |

部署另存为模板的推荐向导逐项列出：普通值保留为默认值或恢复参数占位，主机固定绑定改为选择条件或移除，密钥仅导出逻辑参数与授权引用而不解密。用户必须解决所有待重绑项后才能完成。具体导出默认值、全量密钥扫描边界和跨空间引用重绑方式待产品裁决；不能以“界面打码”代替内容检查，也不承诺任意用户文字中的敏感信息都能自动识别。

文件、应用模板、变量读取和部署执行继续使用原有权限，不新增一个能绕过细分授权的“导出所有”权限。导出不调用variables.reveal，不把部署者主机地址/工作目录当作所有用户可发布的信息。C04～C07的确切权限串与新REST资源模型尚未定义，列为开发前接口评审项；不得在UI先放无法闭环的按钮。

### 14.11 关系图与健康的可判定规则

第一层按实际放置将服务/实例画在主机分组内；第二层区分承载边、dependsOn顺序依赖、入口/端口以及运行时网络连通边。每条边带类型和方向，不能将启动顺序解释成已建立网络连接。文件中的任意字符串不通过正则猜测为网络拓扑；通用链路声明模型源未定义，待补，不向现有deny_unknown_fields文档硬塞新属性。

| 信息 | 状态/展示契约 |
|---|---|
| 部署执行 | 沿用pending/queued/running/succeeded/failed/needs-review等已有状态及目标状态；状态字典以接口为准，不把succeeded改称永久健康 |
| 实例健康 | 有当前有效观测才显示正常或异常；无观测显示未检测；采样失败/过期显示未知/过期，不显示绿色 |
| 连接健康 | 成功观测为绿色实线+成功文字；失败观测为红线+叉号+错误摘要；从未观测或过期为灰色虚线+文字；红线表示观测失败，不武断定位为物理网线断开 |
| 部分故障 | 图中标明具体实例/方向/协议；总体标为部分异常，不隐藏健康成员；HTTP/TCP成功不能证明仲裁、复制或数据一致性 |
| 探测证据 | 源实例/执行节点、目标实例/地址、协议/端口、采样时间、结果及错误摘要；来源与目标均受空间授权；恢复后保留既有告警/审计策略 |
| 双向与代理 | A→B成功不推断B→A成功；经代理或从控制面探测必须标视点，不能冒充源服务网络环境 |
| HA角色 | 仅协议适配器确认leader/primary/quorum/replica等角色；stable/stateless、replicas数量不直接等于主从角色 |
| 交互 | 选择节点/边显示配置路径、当前修订、端口和观测证据；跳转日志/终端沿用原权限；图上拖拽不直接改运行部署 |

当前10秒是前端实例汇总刷新周期，不是新链路探测周期。新探测的周期、超时、连续失败/恢复阈值、数据过期窗口、观测保留与告警去重均未在项目定义，禁止随意填数。图布局使用视图状态，不能因刷新重排导致用户丢失选择；布局持久化位置/期限尚待定义，不修改部署语义。React Flow与relation-graph的最终选择在节点分组、自定义连线、布局稳定性、键盘可达和实际资源测试后评审；默认先验证现有React Flow复用，不新增依赖。

### 14.14 本次界面收敛：统一创建入口与配置详情

本节为用户在2026-11-13补充指出详情布局不一致、NATS模板进入普通应用表单报错、蓝图创建仍为另一套页面后，授权修复的界面范围。它不代表14.13的完整包版本、导出或主动网络探测方案已经实施。

收敛契约：
