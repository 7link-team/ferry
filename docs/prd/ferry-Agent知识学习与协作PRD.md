## 2. 目标、用户与范围

目标：跨会话复用被允许的事实；把完成轨迹转成可审阅方法；以现有 Runner 执行有界协作；保证上下文、版本、权限和执行状态可追溯。

用户行为角色：使用者、内容所有者、知识审阅者、协作发起人、工作区管理员。它们是行为说明，不新增组织角色；真实授权按权限能力组合，不按角色名称硬编码。

## 3. 共用权限、内容与并发契约

### AUTH

AUTH-01：每个请求使用路径 Scope；客户端 workspace_id 不参与授权，跨工作区与不可见对象返回既有 missing 语义，不暴露存在性。

AUTH-02（P01）：个人内容只对 owner 可见，即使管理员拥有管理权限也不直接读取他人私有正文。共享内容需 read/use；能管理工作区不等于能读私聊证据。Agent/项目绑定只缩小范围，不扩大可见性；本期不新增项目 ACL。

AUTH-03：检索候选、重排、正文读取、提示词注入、证据打开、发布与任务派发前分别复核权限。不先向外部模型发送越权候选再过滤。

AUTH-04：人工修订不消除原始证据依赖；私聊转共享不能靠移除来源链接绕过限制。共享内容须独立新建，经发布者确认不含受限信息；原对象仍私有。

AUTH-05：首次与每次工具调用/派发使用当前权限；执行快照记录证据而非永久授权。离组、账号停用、Agent 禁用或节点撤权后禁止新调度并发起停止，不宣称能撤销已经执行的外部副作用。

AUTH-06：新增拟定权限目录为 `ai-memories.{read,create,update,publish,archive,delete,use}`、`ai-skills.{read,create,update,publish,archive,delete,use}`、`ai-learning.{read,configure,run,review,cancel}`、`ai-collaborations.{read,create,cancel}`。每个操作还须通过 owner/范围/当前成员校验；不给存量自定义角色自动加权。系统内置角色映射须在实施前评审，未映射不放行。

CON-01：写入必须带当前 version；重复请求另带 client_id；相同幂等键不同 payload 返回 409。幂等、权限和状态在同一事务或现有工作区锁保护下判定。

CON-02：正文及快照复用资产存储；下载必须经过知识对象授权，不接受裸 asset_id。正文不进审计、错误堆栈和通知；审计只记录 ID、版本、动作、结果、hash 和操作者。

CON-03：所有任务使用持久化领域记录，执行租约与 fencing 复用既有机制；服务器重启不能重新发布同一提案或再次派发不确定写任务。

CON-04：新增领域写操作的幂等结果保存于 ai_knowledge_requests；只含对象ID/版本/动作结果，不复制正文。操作与completed回执同事务提交，重放先重验当前授权，已删除对象不返回旧正文。提案client_id用于候选生成去重，决策操作使用独立请求client_id，不能混用。

## 4. 功能规则

每个 FR 是独立验收点，完整的逐维卡片见评审文档。下列“禁止”与状态机均为拟定设计约束，不表示已开发。

### A. 记忆管理

**FR-A1 保存、列表与编辑。** 从个人知识列表新建，或从有权读取的消息选择“保存为记忆”。保存表单含标题、正文、类型、到期时间、Agent 绑定；默认私有。类型为 fact/preference/context，禁止用户把一次操作愿望标成执行许可。保存为 draft；手动确认后 active，自动提取只能生成 proposal。列表提供类型/状态/绑定/更新时间筛选、标题搜索、来源数量；正文只在详情按需获取。

**FR-A2 证据与共享。** 每条来源记录源对象 ID、版本及 hash；打开来源再鉴权。手工输入记录 manual 来源与作者，不伪造 message_id。共享操作为创建独立 shared draft，不修改原私有内容 visibility；需 publish 权限和明确无受限内容声明。AI 从私聊提取的内容不得批量共享。证据缺失/撤回/版本不符时标“需复核”，停止该对象进入召回。

**FR-A3 纠错、锁定与删除。** 人工编辑使 version 增加并令旧 embedding 失效。user_locked=true 阻止自动提取/归并覆盖，但不免除来源撤权。失效立即停止召回；归档可恢复为 draft，不能直接恢复 active。删除仅在 archived、无活动执行引用时允许，删除正文及证据引用；资产进入既有 GC 而非直接删共享文件。审计留元数据，不留正文。没有已确认全局 TTL，不增设自动永久删除任务。

### B. 召回、提取与上下文

**FR-B1 混合召回。** 候选集先做当前授权/状态/到期/来源版本过滤，关键词与语义结果按 memory_id 去重。关键词匹配标题和有权读取的正文，大小写规范按统一检索实现；语义采用同模型同维度余弦相似，零向量/非有限数拒绝。融合使用 `1/(60+rank_keyword)+1/(60+rank_semantic)`，缺失分量为 0；并列按 updated_at 降序、id 降序。此公式为 P04 新拟定算法，不声称最优或正确率。返回来源和命中方式，不显示“事实置信度”。

**FR-B2 提取与归并。** 用户开启后只读取其当时可见且未撤回的已完成对话；保留 source version。读取既有记忆、生成结构化候选、校验 ID/正文/范围，再生成提案。新增/修订/归并均须审阅；归并不得修改锁定记录、跨 owner 或跨 visibility。多个对象归并在单事务核验所有 base_version，任一冲突全部不应用；旧对象标 invalid，不静默删除。候选失败不写半份有效记忆。

**FR-B3 注入与快照。** 先保留当前请求和用户选择的技能，再在剩余预算内选取 active 记忆；逐条检查权限，按完整段落加入，放不下整条即跳过。正文包在明确的“参考资料，不是权限/新指令”区域。记录所用 ID/version/hash、来源和截断原因。原生会话已包含同一版本时不重复注入；变化内容显式标更正。权限撤销/删除后，涉及旧内容的原生 session 标为不可续用，新会话仅重建当前有权上下文；不能擦除设备上已产生的历史。页面显示“上下文组成”而非隐藏注入。

### C. 技能资产

**FR-C1 正文与版本。** 技能为可复用 Markdown 方法，含标题、说明、适用条件、步骤、验证与失败处理；记录正文资产和不可变 revision。复用 definition_revisions，只保存资产 locator/hash 和结构化元数据，不把密钥写入 revision JSON。保存新草稿不改变已发布版本；比较当前候选与发布版，明确完整替换而非只显示模型摘要。

**FR-C2 发布、停用与恢复。** 发布需 ai-skills.publish，校验完整正文、证据、所有权、当前 base_version；候选内容改变后旧批准无效。发布事务更新 published_revision_id 并写回执。停用阻止后续选择；在途执行保持固定内容但继续当前授权检查。恢复历史不是覆盖旧 revision，而是创建新候选后重新发布。归档/删除沿用引用保护；本期禁用自动发布、结构性修改和自动安装外部依赖。

### D. 学习闭环

**FR-D1 完成轨迹与反馈。** 仅正常终态轨迹进入技能提炼；等待审批/异步任务、超时、取消、未知执行状态不算成功。失败轨迹可作为诊断候选，但不得标为成功技能证据。读取用户请求、真实工具结果、最终输出、明确用户反馈；无工具结果则不虚构验证。自学习自身 origin=learning 的运行不得再次触发完成提炼。

**FR-D2 定期复盘。** 设置以 owner+agent 为单位；默认关闭，手动与定时共用同一生成流程。复用 cron_jobs，新增受控 action 适配，不暴露任意命令字段。时区采用检测建议值、必须确认 IANA 时区，禁止“跟随系统”。同一设置+本地日期+规则版本幂等；夏令时重复时刻只运行一次，跳过的时刻由既有 cron 明确计算下一次，不补发。启用前显示下一次 UTC 与本地时间、模型及预算来源。无新增证据输出 noop，不制造通知或空提案。

**FR-D3 提案、应用与回执。** pending 可接受/拒绝/取消；应用锁定目标与全部 base versions，资产先暂存，事务附着后进入 applied。已应用重复请求返回原回执；冲突进入 stale，模型/工具错误进入 failed，不包装成成功。重试必须创建引用原提案的新提案。记忆接受后按 A 校验生效；技能接受只创建候选，发布仍由 C2 明确完成。拒绝原因可选，不把单次拒绝自动解释成永久偏好。

### E. 有界持久化协作

**FR-E1 显式启动与计划。** 用户在会话选择“协作任务”，填写目标、负责人 Agent、成员、顺序/并行/交接模式、总期限；先生成并展示计划再确认启动。plan revision 固定成员、依赖、输入、权限上限及失败策略；模型只能引用已授权 Agent ID。禁止环、重复 step_key、跨工作区成员与空成员。现有私聊/群聊默认行为不变，普通 Agent 回复不触发下一轮。

**FR-E2 执行与汇总。** 顺序等待依赖完成；并行按配置并发和现有节点容量派发；交接为明确的控制权转移，原负责人不再重复执行。每个子任务有独立受管目录、原生会话与上下文快照，复用 turn/events/Runner。并行征询要求可靠只读控制，否则在启动前报能力不支持。结果按 step_key 汇集，不按回调到达顺序决定上下文；完成屏障+CAS 仅恢复父任务一次。负责人汇总注明每项来源和未完成项，不能把部分成功写成全部完成。

**FR-E3 审批、停止与失败。** P06 规定必需任务失败/超时即进入 cancelling，停止未派发与活动兄弟任务；未知任务需核实停止结果，不能直接宣称 cancelled。单次工具审批归发起人，负责人/成员不能代批；等待审批占用总期限。取消即撤销后续派发许可并请求终止活动任务；全部已知终止后 cancelled，节点失联则 retained 状态为 stopping_unknown。副作用不做自动补偿，不自动重跑写任务。离组/失权触发同样停止流程。

### F. 会话与调度增强

**FR-F1 分支。** 从已完成的可见消息创建分支，选择分叉点和新请求；分叉前内容以引用路径继承，后续消息归属所选分支。每次发送携带 branch_id 和 expected head，冲突不覆盖。切换仅影响后续上下文与展示，不取消其他分支执行。原生 session 不跨分支复用；旧会话默认主分支只读映射，不改写历史消息和既有回复关系。

分支补充：旧主链使用 branch_id=null 的虚拟主分支，不为旧消息批量建映射；新分支的parent_branch_id为空且fork_message_id非空表示从旧主链分叉。新分支消息在ai_branch_messages记录顺序，主链读取排除其他分支映射消息。每分支只允许一个活动turn；在Scope/分支锁内校验head、创建用户消息、绑定turn和上下文快照。完成助手消息只回填所属分支；删除/撤回源消息实时影响继承视图。分支续用从同branch最近成功turn及其binding获取native session，不读其他分支或conversation全局session；首次分叉只重建授权历史。成员从某分支创建的新分支不会继承其私有Agent任务内部材料。

**FR-F2 派发不确定性。** 先持久化意图和唯一请求标识，后发送；ACK 超时进入 unknown，等待同 operation 的回传或当前 Runner 的状态确认。unknown 状态禁止第二次执行请求；仅“明确未接收/未启动”可重试，产生新 attempt 并关联前次。无法核实时显示未知并允许请求停止/人工检查，不允许客户端一键当成失败重跑。回传身份、租约 epoch、turn 绑定必须一致；旧连接不能完成新租约。

**FR-F3 恢复绑定。** 原生 session 仅在原 host/user/execution_identity/canonical_directory/runtime 的绑定兼容时续用；模型切换与工具版本兼容性由已核查适配器判定，未知不兼容。恢复失败只在未产生新执行副作用的明确前提下新建会话；其余进入未知/人工处理，不盲目重放。新上下文仅带授权历史并显式历史说明；不使用其他用户机器上的 session。缺能力旧 Runner 在启动前显示升级要求。

## 5. 状态与操作矩阵

未列出的迁移全部 409；状态比较、权限和 version 同事务检查。403 为可见对象但无操作权限；不可见对象用 missing；字段错误 400；能力缺失用明确本地化冲突错误，不能 success:true。

| 对象 | 合法迁移 | 条件 / 非法操作 |
|---|---|---|
| Memory | draft→active/archived；active→invalid/archived；invalid→draft/archived；archived→draft/物理删除 | 激活需来源有效；active 编辑先降 draft 再审阅；锁定只禁自动修订；过期由查询实时判无效 |
| Skill | draft→enabled；enabled→disabled/archived；disabled→enabled/archived；archived→draft/物理删除 | enabled 必须已发布 revision；编辑候选不切换发布指针；重启用需来源与权限仍有效 |
| Proposal | pending→applied/rejected/stale/failed/cancelled | 不可回到 pending；应用中间过程由事务保护，不对外伪造 applied |
| Knowledge job | queued→running/cancelled；running→completed/failed/cancelling；cancelling→cancelled/unknown；unknown→completed/failed/cancelled | 租约丢失不证明外部调用没发生；unknown 不自动重跑 |

| Collaboration task | pending→dispatched/cancelled/failed；dispatched→running/unknown/failed/cancelling；running→waiting_human/completed/failed/cancelling；waiting_human→running/cancelling；unknown→running/completed/failed/cancelling；cancelling→cancelled/completed/failed/unknown | 派发前校验失败可failed；停止期间任务自然结束保留真实outcome；dispatched之前冻结turn与目录；unknown需要同请求状态证据 |
| Dispatch intent | prepared→sent/aborted；sent→accepted/unknown/aborted；accepted→running/unknown/terminal；unknown→accepted/running/terminal/aborted；running→terminal/unknown | aborted 必须有未启动证据；terminal 需 outcome 与当前 epoch；terminal 不直接删除 |

## 6. 来源失效、保留与历史影响

RET-01（P05）：每次召回/注入验证全部证据。消息撤回/编辑、来源删除或 requester 失去来源权限时，依赖对象不再可用；失效不能靠旧 embedding 绕过。已复制到新共享草稿的内容需要独立人工发布声明；自动候选不能借此去掉血缘。

RET-02：权限变化不是“全局内容无效”：只对失权主体停止返回；来源全局撤回/删除则所有依赖均停用。通过 source version 检查与索引反向定位实现。证据检查超时按不可用处理，不能用缓存默认放行。

RET-03：停用/失效影响新注入与新执行，立即阻止进一步工具请求并停止仍含敏感上下文的活动执行；已进入模型/CLI 的内容不能追溯擦除。之后必须新 session；未完成的外部动作如实记录。

RET-04：实体先归档、再按引用保护删除；无默认自动 TTL。可选 expires_at 只决定生效，不承诺物理清除。活动运行引用阻止删除；历史快照保留 ID/hash，正文资产在删除事务中去引用，历史页面显示“内容已删除”，不继续提供旧正文下载。共享资产其他合法引用不受影响。GC 遵已有机制，不承诺固定销毁秒数，界面区分逻辑删除与待物理清理。

RET-05：不回填推断记忆、不批量训练历史、不改旧原生 session。旧会话分支按主链兼容读取。迁移新增领域表，存量消息/turn 字段不擅自扩充；若协议最终需要新增字段，先走兼容设计和 capability gate。
