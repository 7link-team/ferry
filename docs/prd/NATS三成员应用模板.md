# NATS 三成员应用模板

## 范围与依据

本期将《应用高可用拓扑与多部署驱动方案》中的 NATS JetStream 场景接入现有应用模板、配置模板和部署链路。依据为 `test-ha-topologies.py` 的固定镜像与协议实验、`deployments/manifest.rs` 的 v2 定义及 Stack overrides、`deployments/mod.rs` 的空间内配置模板/变量绑定、`test-deployments.py` 的 SSH/HostAgent 驱动。

初始化三份独立数据卷、三个单副本成员和一份可复用配置模板。Compose 验收进程故障；Stack 使用三个独立 daemon，成员分别固定到 `node.labels.ferry-nats == a/b/c`，卷不跨主机迁移。目标 Swarm 必须由用户预先配置这三个标签，且三成员位于不同节点；不满足约束时部署失败，不取消约束退化为同机。

本期不增加调度器、数据库表、协议状态管理页面、自动创建 Stream、生产 TLS、跨主机卷迁移或全停恢复控制器；不声明 PXC/Redis Sentinel/TiDB 已支持。模板只为新空间创建副本，不启动服务、不生成密钥、不覆盖旧空间。

## 配置与流程

配置模板名为稳定引用 `example-nats-config`，内容由源码提供，参数为空；每成员通过环境变量提供名称、客户端通告端点和客户端认证 token。路由使用应用隔离网络内 `nats-a/b/c:6222`；6222/8222 不发布到主机。客户端端口独立发布，用户必须填写客户端实际可达的通告端点，不能用监听地址代替。

| 应用参数 | 类型 / 必填 / 默认 / 限制 | 来源与作用 |
|---|---|---|
| token | string，必填，无默认，既有变量名规则 | 选择本空间 deploy 作用域密钥变量；写入 env.valueFrom，模板不保存明文 |
| config | string，默认 example-nats-config，1～60字符 | 当前空间配置模板名称或 ID；删除/改名后用户重新绑定 |
| port_a/b/c | integer，默认4222/4223/4224，1～65535 | 三个客户端发布端口；重复或已占用由既有部署校验/引擎拒绝 |
| advertise_a/b/c | string，必填，无默认，1～255字符 | 对应成员的客户端可达 host:port；NATS 自身校验地址格式，不增加伪造的通用地址规则 |

每成员使用固定镜像 digest、512Mi 内存限额、独立 `/data` 卷、独立 server_name。HTTP `/healthz` 检查成员进程；三副本 Stream/consumer 的仲裁与数据可用性通过协议验收独立证明，不能由 HTTP 200 推断。Stream 副本由客户端创建时选择，模板不将所有 Stream 自动设为三副本。

流程：创建空间→选择模板→绑定密钥变量/端点/主机与模式→生成→保存→预览确认→部署。未绑定、外空间引用、角色不足、端口冲突、约束不满足、健康失败均使用现有错误链路；失败不标成功。配置模板沿用引用保护、历史快照和执行审计。应用删除不自动删除数据卷；重启、回滚不重新初始化或清空数据。
