# PXC 三节点部署与恢复方案

状态：方案与隔离验证；不是已交付的生产功能。关联：主方案“有状态服务模板要求”、APP-HA-01、APP-PXC-CAPABILITY-01。

通用架构以《应用高可用拓扑与多部署驱动方案》为准；本文件仅为首个PXC适配器样本，不把Swarm或PXC当全部HA方案。

## 1. 目标、来源与本轮边界

用户目标：一个应用部署三个 PXC 数据节点，支持多节点写入、健康监控、单节点故障后继续服务，并明确恢复和重新调度的行为。

项目依据：`docs/ferry-运维平台产品与技术方案.md` 的有状态拓扑、Swarm 放置和控制面边界；`deployments/manifest.rs` 的 v2 定义、独立服务、持久卷、放置约束和高级 healthcheck；`scripts/test-deployments.py` 的隔离 Docker daemon 故障测试。镜像入口行为参考 Percona 官方 Docker 文档及 percona-docker 仓库，仅作为外部协议依据，不复制其实现。

本轮交付：本方案、可重复的隔离验证脚本、CI 工作流、逐项真实结果。测试直接调用隔离 Swarm，验证数据库与调度前提；不冒充 Ferry 表单/API/Runner 全链路验收。

本轮不做：新增生产自动恢复控制器、UI/接口/数据库迁移、向用户主机部署、生产发版、存量 PXC 自动接管、自动跨区容灾或任意本地卷搬迁。完整产品接入须按第 7 节推进。

## 2. 拓扑与运行契约

一个逻辑应用包含 `pxc-a`、`pxc-b`、`pxc-c` 三个独立服务，均为一个副本，绑定三个不同节点和三个独立持久卷。禁止把同一 PXC 服务直接改为三个无身份副本，禁止多个 mysqld 共用一个数据目录。

复用 Swarm 放置/重启/任务状态；Ferry 负责配置、鉴权、发布预览、审计和展示，不与 Swarm 同时重启同一任务。生产控制面采用三个 manager；测试采用三个独立 daemon/manager，共享 CI 宿主内核，不能认证物理机隔离。

镜像固定版本与摘要。首次候选为 `percona/percona-xtradb-cluster:8.4.11-11.1` 的 amd64 摘要 `sha256:a002b7654a22cb29b2af3e1010b2ad5e5ffdef1dc2eece8bfdf974d09746df44`，本轮未通过；独立复测候选为官方8.0镜像的 amd64 摘要 `sha256:ca15bf7f3b53464a546b57a2a2a3e4cd67cedc6ad25c079e1461128465b649ff`。不同镜像的结果分别保存，不继承PASS；这是实验版本选择，不是系统默认版本或生产版本推荐。生产还须记录版本支持周期、镜像来源和升级兼容结论。

首次仅在三个全新数据目录、已确认无现存集群时允许 a 引导；b、c 按顺序加入。三成员同步后，把 a 改为普通加入者；三个服务均保留非空成员发现地址，重启不再执行首次引导。全停不自动清除数据或强制创建 Primary。

生产启用 Galera/SST 加密、专用备份与健康账号，凭据引用既有空间凭据/变量；服务间端口仅集群网络可达。CI 为隔离实验使用临时密码、私有网络并关闭集群传输加密，不能把该配置作为生产模板。

## 3. 健康、入口和状态

| 层次 | 判定 | 动作 |
|---|---|---|
| 进程存活 | mysqld/socket 可响应 | Swarm 处理进程退出；不因暂时 Donor/Joining 而反复杀进程 |
| 可接业务 | `wsrep_cluster_status=Primary`、`wsrep_connected=ON`、`wsrep_ready=ON`、`wsrep_local_state_comment=Synced`，且业务连接正常 | 客户端入口只接入满足条件的成员 |
| 集群完整 | 三成员、同一非空 cluster UUID、全部同步 | 展示健康；两成员可写时展示降级，不能仍显示完整健康 |
| 信息新鲜度 | 带采集时间；连接失败或过期 | 展示未知/不可达，不能沿用旧绿灯 |

入口方案采用经过 Galera 状态感知配置的 ProxySQL 或 HAProxy；三数据节点可写不等于建议任意业务随机多点写入。默认建议单写入口以减少热点冲突，多写入口是显式选项，并由业务处理认证冲突重试。具体入口产品、镜像版本及读写策略在产品接入前确认为配置项；本轮用直连各成员验证数据库能力，未实现入口高可用。

不把 HTTP 200 或 `mysqladmin ping` 当成数据库可写。当前 Ferry 通用探针为 HTTP；高级容器 healthcheck 可以表达 SQL，但统一的 PXC 观测与入口联动仍需产品接入。

## 4. 故障恢复与调度

| 场景 | 预期行为 | 禁止行为 |
|---|---|---|
| 一个容器崩溃 | 同节点同卷重新拉起，加入现存 Primary；剩余两成员继续写入 | 清空数据、再 bootstrap |
| 一个节点断网 | 两成员保持 Primary；孤立成员拒绝业务写入；网络恢复后重新同步 | 孤立节点强制新建 Primary |
| 一个主机离线 | 其余两成员降级服务；本地卷所属服务因放置约束保持 Pending；主机归队后原卷恢复 | 在其他节点新建同名空卷并称为原数据迁移 |
| 一个数据卷丢失 | 原节点/进程已停止且被隔离后，空卷作为加入者从健康集群 SST；完成同步后接流量 | 未隔离旧成员就复用相同身份 |
| 有备用主机需替换成员 | 先隔离故障身份；创建新身份/新卷，加入健康 Primary，验证同步后移除旧身份 | 同一身份在两处并行启动 |
| 全部成员停止 | 允许 Galera 自身恢复同一 Primary；不能恢复时进入人工恢复。比较 UUID/恢复 seqno 与 safe_to_bootstrap，选择唯一候选，审批后操作 | 自动选第一个节点、同时引导、强制忽略仲裁 |

三台机器且一台不可用时，没有第四个故障域可重建第三个成员。自动替换需要备用容量，或已验证的共享/远程块存储与 fencing；这两者不由 Swarm 本地卷自动提供。本轮验证原卷归队和空卷重新同步，不声称实现跨主机持久卷迁移。

## 5. 可重复验证与证据

入口：`.github/workflows/pxc-acceptance.yml`、`scripts/test-pxc-swarm.py`。只在专用 CI/实验 Docker 主机运行，脚本要求显式实验环境标识；所有资源带唯一前缀，退出只清理自己创建的资源，不初始化宿主 Swarm。

| 用例 | 核验 | 证据 |
|---|---|---|
| PXC-01 | 三独立 daemon、三个不同任务节点、独立卷；三成员同 UUID/Primary/Synced | 节点/任务及 wsrep 快照 |
| PXC-02 | 分别从三个成员写入唯一主键；所有成员行数与有序内容摘要一致 | 写入结果、数据摘要 |
| PXC-03 | 杀死一个任务，Swarm 替换，同卷恢复且数据不丢 | 前后任务 ID、wsrep、摘要 |
| PXC-04 | 断开一个 daemon 的网络，两个成员继续写；孤立成员写失败；恢复后三成员数据一致 | 分区/恢复快照、成功/拒绝结果 |
| PXC-05 | 停止一个 daemon，剩余成员可写；绑定卷的服务不在其他节点冒名启动；归队恢复 | daemon/服务任务状态、数据摘要 |
| PXC-06 | 停止 c，删除其专属实验数据卷；以 joiner 重新创建，三成员恢复一致 | 空卷确认、同步日志、摘要 |
| PXC-07 | 三节点全停再启动：记录同组自动恢复或人工恢复要求；所有服务均无强制 bootstrap；自动恢复必须保持 UUID 与数据一致 | 全停状态、非空发现地址、恢复结果 |

PXC-07 的“需要人工恢复”不是自动恢复通过；报告分开记录安全控制与自动恢复能力。初始化/断网等均有超时，失败保存首失败及脱敏诊断，不删断言或用旧提交替代。

CI 资源仅证明共享宿主内的独立 daemon、集群协议和故障行为；没有验证真实物理断电、跨机防火墙、云盘 fencing、异地延迟、生产负载、备份还原、版本滚动升级及数据库代理入口。

## 6. 设计评审

| 维度 | 结论 |
|---|---|
| 事实来源 | 第 1 节项目内依据；外部仅协议与镜像入口参考；拟新增能力明确标后续 |
| 本期/不做/灰度 | 本期方案+隔离测试；不部署产品新能力；灰度无，实验显式开关 |
| 流程/状态操作 | 初始化→加入→健康→降级→恢复；非法多 bootstrap、身份冲突和空卷冒名禁止；失败保留诊断 |
| 异常/状态覆盖 | 无 Docker 拒绝；镜像拉取/初始化/恢复超时失败；零可用成员停写；资源不足保持 Pending |
| 权限/隔离/审计 | 实验独占资源；不得访问用户4291/空间/凭据；产品接入复用部署权限、空间作用域和提交审计；本轮实验阶段以用例日志追溯 |
| 删除保留 | 仅删除本轮创建的容器/网络/卷；数据卷删除只允许明确的PXC-06；日志报告保留CI附件；不删除用户数据 |
| 计算逻辑 | 无金额；数据一致性用行数、有序内容SHA256和cluster UUID，不能只看副本数 |
| 模式/字段联动 | 本轮无新增页面；测试固定三成员、每服务一副本、独立卷/节点；生产参数和入口策略在接入前明确 |
| 校验规则 | 固定摘要、唯一实验前缀、Linux/Docker/显式授权环境、三不同节点；严格超时及状态/数据断言 |
| 数据模型/时间审计/索引/SQL DDL | 无产品表或迁移；实验数据表由测试脚本创建，临时ID主键，不作为产品业务模型 |
| 配置来源/文案/响应式/时区 | 实验参数为开发配置；无新增产品文案、表单、时区字段或页面，三端交付无新增；PRD暂缺Figma，不冒充覆盖 |
| 历史数据/核心流程/版本 | 不影响用户数据、4291或现有部署流程；兼容性无改变，禁止把实验脚本标成生产模板 |
| 三方依赖 | Percona镜像、Docker/Swarm、GitHub Actions；不引入产品运行依赖或复制三方源码 |
| 冲突/测试追踪 | 和已有“本地卷不迁移、无PXC认证”边界一致；PXC-01～07对应脚本检查；最终结果由实际CI证据补录 |
| 模糊表达/评审结论 | 本期行为可判定；生产入口、存储和审批接入标为后续，不在本轮编造实现 |

## 7. 产品接入与生产门禁

1. 本轮实验验证数据库/调度方案，保留实际失败与修正记录。
2. 增加版本化 PXC 模板和完整变量/凭据绑定，拒绝三匿名副本；通过 Ferry API→预览→SSH/Agent→Swarm 两条链路验收。
3. 增加只读 PXC 状态采集、过期状态、入口摘流及集群降级展示，补齐三端/多语言/权限与操作审计设计。
4. 恢复操作独立于普通容器重启；全停 bootstrap、丢卷重建与成员替换必须预览、隔离证明、审批及可追溯记录。
5. 在三台真实机器及备用节点验证断电、网络分区、资源不足、恢复、备份还原和兼容升级；跨主机卷迁移单独认证。完成后才能标记生产支持。
