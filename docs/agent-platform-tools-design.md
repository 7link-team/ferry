# Agent 平台工具与角色授权

状态：已实现并完成本地真实 Codex MCP 验证，等待用户验收；用户已确认 Runner 内置桥、复用角色权限、覆盖授权业务接口。

## 链路与边界

模型 → CLI 原生 MCP 客户端 → Runner 内置 stdio MCP 适配器 → 本回合本机桥 → 已认证 Runner 会话通道 → 平台工具网关 → 现有业务路由/处理器。

API 模型后续使用同一网关的函数调用适配器，不复制鉴权和业务实现。Skill 只提供使用指引，不承担授权。Runner 不持有用户登录 Cookie、数据库账号或平台长期 API 密钥；本机桥能力仅对本次执行有效，结束回收。模型返回的 workspace_id、用户身份或权限不得改变服务端绑定。

每次调用重读发起用户、Agent 状态、角色及会话权限。Agent 绑定已有工作空间角色；有效权限为发起用户与 Agent 角色权限交集。无角色的存量 Agent 不自动获得平台权限。角色修改/删除和成员停用在下一次调用生效。CLI 文件访问模式与平台角色授权分开，不能相互替代。

调用覆盖现有工作空间业务接口，而非只实现流水线或数量查询。所有接口继续经过原处理器的数据权限、状态、参数、版本及业务规则校验。不直接访问数据库、不代理外网、不允许模型指定鉴权头。工具目录提供项目内接口依据；查询失败返回可区分的权限、参数、记录缺失或服务错误，不允许伪造成功结果。

读操作可直接调用；写操作先展示具体操作及参数，请用户确认。确认后重查权限，只执行一次；中断或结果未知不自动重放。原业务审计保留发起用户，工具执行轨迹同时记录 Agent、会话、回合和结果。不回显凭据。

## 交付与验收

1. 通用工具网关、已有路由复用、角色授权与实时撤权测试。
2. Runner MCP 桥与六类 CLI 适配；不支持工具的旧版本须明确失败，不能静默退化为无工具会话。
3. Agent 表单复用角色选择器；六语及 Desktop/Pad/Phone 查看与编辑验证。
4. 主机、仓库、应用部署、构建流水线、节点工作流等按每个接口/权限分别验证：授权成功、撤权拒绝、数据归属拒绝、菜单显示不代替接口授权。
5. 隔离实例真实 MCP→服务端→业务接口链路与写操作确认验证；准备专用验收数据，备份后更新本地，保留原数据/密钥/运行实例。

空间边界已确认：同账号在多个空间分别授权；会话和工具绑定当前空间，服务端重新解析该空间 Scope，不新增长期空间 Token，不接受工具参数改写空间。

## 实现契约与容量边界

- `ferry_discover(search, offset)` 从实际工作空间路由生成目录，每页20项；目录包含方法、相对路径、处理器签名及项目内 DTO 定义。静态权限候选仅辅助发现，实际调用仍经过业务处理器鉴权，不把目录可见性当作授权成功。
- `ferry_request(method, path, body, transfer)` 使用当前会话空间，不接受用户身份或鉴权头。支持 JSON、Base64 原始文件、单文件 multipart；响应支持 JSON、文本与 Base64 文件。交互式 WebSocket 终端使用原浏览器协议，工具通过同权限的 `POST /nodes/{id}/commands` 执行非交互命令。
- 每回合最多128次工具请求，最多16个等待任务，请求 JSON 上限1MiB，响应上限256KiB，沿用回合18MiB总事件限额。大列表读取 `total` 并分页；超限返回明确错误，已执行写入不因响应超限自动重试。
- 主机命令沿用 `hosts.terminal`、当前空间主机通道和操作审计；超时1～300秒、合计输出128KiB，达到输出上限或请求取消即发送取消信号。
- 写参数使用现有 Vault 按空间/回合/请求标识加密保存；公开确认、事件和响应移除密钥。带令牌的连接命令同步脱敏。确认后重查角色与用户权限，事务内部刷新权限仍受委托上限约束。
- 构建/工作流/部署提交后沿用已有异步任务授权与取消规则；角色撤销阻止后续工具调用，不隐式撤销已确认提交的业务任务。任务详情和停止入口仍使用各自业务权限。
- Codex 与 Claude 使用原生 MCP；Gemini/Qwen/OpenCode 使用 ACP MCP 配置，Pi 使用其扩展工具接口。标准协议夹具与真实客户端验收分别记证据，不把协议夹具通过等同于六种商业模型全部实连。
- 本期无数据库迁移；平台级超级管理员身份不会传给 Agent。原用户权限不变，Agent 未配置角色时无平台访问权限。
