# 监控与应用健康一期设计

状态：2026-11-11 用户授权第一期实施；参数采用可配置及默认值，聚合规则已确认。本文是本期实施契约，不将外部产品的能力当作已实现事实。

## Implementation Plan

### Goal / Requirements
三个对象层次：复用主机系统监控，持续观测应用服务实例，用入口探测和实例完整性共同展示应用健康。统一复用告警及通知。

### Existing Implementation / Reuse
- `hosts/monitor.rs`、`protocol::HostMonitor`：主机采集、采样时间、磁盘列表及跨服务实例归属。
- `deployments::{project,directory,quote}`、`deployments/modes.rs`：Native/systemd、Docker、Compose、Swarm资源身份；manifest服务与副本；成功部署修订是运行配置来源。
- `hosts::remote::open` / `HostChannel`：所有主机命令入口，不新增SSH或Runner协议。
- `notifications/alerts.rs`：规则、触发/恢复事件、去重及投递；`notifications/center.rs`：共享通知。
- `Scope`、`resources::resource`、`ResourceTable`、`ResourceForm`：空间隔离、权限、列表信封与前端配置。

### Task Decomposition / Execution Mode
Direct。迁移、采集与聚合依赖同一契约，先顺序实现；不创建子代理。

### Design
新增health-checks资源，HTTP/TCP由当前服务端网络发起，runtime通过指定主机的HostChannel读取部署服务运行信息。runtime只执行内置只读检查，不接受任意脚本。HTTP/TCP可以绑定应用入口或应用服务，runtime绑定应用及执行主机。界面始终注明执行位置；不声称已覆盖任意内网探测节点。

### Files to Change / Files to Add / Files Not to Change
修改服务器路由/调度生命周期、实体及迁移注册、现有告警目标支持、资源配置/导航/i18n。新增monitoring模块、迁移、前端monitoring资源配置及回归。主机传输、Runner、protocol、DSH/Agent、生产数据、现有迁移及发布流程不改。

### Testing / Acceptance Criteria
工作区check/test、前端typecheck/build；实际HTTP/TCP端点成功/失败/超时；连续触发恢复、过期不恢复、并发抢占与旧结果拒绝、空间/角色/撤权、迁移保全；Native/Docker/Compose/Swarm解析及可用真实环境；三尺寸浏览器及长文案。未有真实环境的引擎不宣称真实验收。

### Risks / Out of Scope
HTTP可达不等于业务正确；进程running不等于协议健康；Swarm任务观测不等于数据库仲裁。MQTT/日志/脚本/主动心跳/自动修复/新调度器为第二期，不实现。无需三方监控产品集成。

## 判定与参数

以下默认值经用户确认；每项配置必须在服务端校验：间隔30秒、超时5秒、连续失败3次触发、连续成功2次恢复、超过90秒无结果标过期、原始结果保留7天。

参数范围：间隔5–86400秒；超时1–300秒且小于间隔；失败/恢复次数1–100；过期秒数不小于间隔加超时且不超过604800秒；保留1–365天。范围是防止零间隔、无限执行与不可判定过期的技术约束，不代表业务SLA。整数拒绝小数/负数/越界。

- 新建默认停用；启用后首次采集前未知，首次成功即可建立健康基线；故障须达到失败次数；已确认故障须达到恢复次数。中间结果展示连续次数，禁止一次成功清掉已确认故障。
- 探测结果分成功、失败、无法观测。目标HTTP错误/连接拒绝/超时是失败；执行主机失联、权限撤回、命令不可用及格式错误为未知。未知打断连续计数，不当作恢复。
- 停用显示暂停，配置变更重置基线；停用、删除、未知和过期不生成伪恢复事件。
- 应用入口达到失败门槛为不可用；入口成功且存在已知异常/不足副本为降级；新鲜观测不足以判断为未知；入口及实例均有完整新鲜成功证据才显示健康。
- 应用始终分别展示入口、每个服务期望副本、观测副本与未知量；无检查、无成功部署修订及不支持的运行环境均未知。使用运行修订而非未部署的新草稿判断期望。
- Swarm通过只读`docker info`获取Cluster ID；同一集群的管理节点观测按该身份合并副本，不把同一主机组中的独立集群合并。缺少身份或命令失败显示未知。身份存于观测JSON，不新增数据库列。
- 扩缩容/滚动更新同时保留当前运行观测及部署执行状态；更新中展示更新中，禁止解释成稳定故障或自动恢复。Swarm只统计期望运行的当前任务，保留节点与任务ID；不把历史已替换任务计作应有副本。

## 数据模型与迁移

使用两张增量表；不改动历史规则/事件；不自动为历史应用创建或启用探测。现有部署失败规则继续表示执行失败。

### health_checks 字段约束

| 字段 | 类型 | 必填/默认/约束 |
|---|---|---|
| id | BIGINT | 必填；雪花主键 |
| workspace_id | BIGINT | 必填；Scope提供，不接受客户端输入 |
| name | VARCHAR(120) | 必填，trim后1–120字符 |
| description | TEXT | 必填，默认空串，最多2000字符 |
| kind | VARCHAR(16) | 必填，http/tcp/runtime |
| role | VARCHAR(16) | 必填，entry/service；runtime仅service |
| deployment_id | BIGINT | 必填，默认0，0表示未绑定；runtime必填实际应用 |
| host_id | BIGINT | 必填，默认0；runtime必填；HTTP/TCP仅0（服务端网络） |
| service_name | VARCHAR(120) | 必填，默认空串；HTTP/TCP绑定服务时必须是运行manifest服务；runtime空串表示全部服务 |
| settings | TEXT | 必填，规范化JSON；参数、地址及HTTP断言 |
| enabled | BIGINT | 必填，默认0，只能0/1 |
| run_as | BIGINT | 必填，配置操作者；后台每轮重查权限 |
| result | TEXT | 必填，默认空JSON；带检查状态、连续次数、观察结果，不含凭据/响应正文 |
| version | BIGINT | 必填，默认1，配置乐观锁 |
| created_at / created_by | BIGINT | 必填，默认0；毫秒/操作者，0=system |
| updated_at / updated_by | BIGINT | 必填，默认0；毫秒/操作者，0=system |
| checked_at / checked_by | BIGINT | 必填，默认0；最后完成时间/0=system |
| due_at / due_by | BIGINT | 必填，默认0；下一检查或抢占期限/0=system |

### health_observations 字段约束

| 字段 | 类型 | 必填/默认/约束 |
|---|---|---|
| id | BIGINT | 必填，雪花主键 |
| workspace_id | BIGINT | 必填，来源检查所在空间 |
| check_id | BIGINT | 必填，来源检查ID |
| result | TEXT | 必填，单次规范化观测JSON，不保留响应正文或凭据 |
| observed_at / observed_by | BIGINT | 必填，默认0，完成时间/0=system |

索引：checks(workspace_id,created_at)、checks(enabled,due_at)、checks(workspace_id,deployment_id)、checks(workspace_id,host_id)；observations(workspace_id,check_id,observed_at)。无名称唯一约束/条件唯一索引；引用同空间校验在工作空间事务中执行。历史资源删除会在下次检查显示未知，历史观测不冒充正常。

DDL由上述字段约束派生，使用SeaQuery分别生成SQLite/PostgreSQL/MySQL；迁移测试验证列、索引、默认值和审计对称，实际生成SQL见文末。数字字段默认值为数据库默认；description、service_name、result的默认值由应用显式写入，数据库不设置字符串/JSON默认值。MySQL使用longtext与utf8mb4_bin，SQLite的integer为64位整数；均不依赖自增主键。

Up只创建新表和索引。应用回退可保留新表并停止新调度；Down拒绝有数据时删除，空表按observations→checks顺序删除；禁止运行到现有数据库。

## 可执行验收矩阵

1. HTTP本地成功、状态不符、内容不符、连接拒绝、超时、重定向不跟随、大响应有界；TCP真实监听/关闭端口。
2. 初始成功建立基线；连续失败门槛触发一次；恢复门槛前不恢复；未知重置计数且不恢复；过期/暂停不恢复；编辑版本拒绝旧采样。
3. 并发调度仅一个抢占成功；故障进程重启后超时可再检查；配置停用/删除期间旧结果不回写。
4. 原主机规则及部署失败规则行为保持；新检查故障用原告警事件和渠道，恢复投递仍走统一通知。
5. 入口健康+某服务缺副本=降级；某服务的多余副本不能抵消另一服务缺副本；过期/未知不报告健康；入口确认失败=不可用。
6. runtime使用运行修订；Native/Docker/Compose/Swarm分别验证命令身份与输出；运行环境缺失明确未知，不当作正常。
7. API401/403、跨空间引用404、后台撤权后不执行；无权的主机/应用信息不泄露。
8. 迁移SQLite实际up/down，PG/MySQL生成SQL与语法结构检查，保留原表数据；未实连引擎单列限制。
9. 1440/900/390/320px、zh-CN/en-US/ms-MY、明暗主题、长名称/空态/错误/版本冲突；Figma暂缺。

### MySql

CREATE TABLE IF NOT EXISTS `health_observations` ( `id` bigint NOT NULL PRIMARY KEY, `workspace_id` bigint NOT NULL DEFAULT 0, `check_id` bigint NOT NULL DEFAULT 0, `observed_at` bigint NOT NULL DEFAULT 0, `observed_by` bigint NOT NULL DEFAULT 0, `result` longtext NOT NULL ) DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_bin;
CREATE INDEX `idx_health_checks_workspace_created` ON `health_checks` (`workspace_id`, `created_at`);
CREATE INDEX `idx_health_checks_due` ON `health_checks` (`enabled`, `due_at`);
CREATE INDEX `idx_health_checks_application` ON `health_checks` (`workspace_id`, `deployment_id`);
CREATE INDEX `idx_health_checks_host` ON `health_checks` (`workspace_id`, `host_id`);
CREATE INDEX `idx_health_observations_check` ON `health_observations` (`workspace_id`, `check_id`, `observed_at`);
