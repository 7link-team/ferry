## Goal / Requirements

用户询问前次研究中值得借鉴的能力能否全部实现。本稿将其归并为六个交付包，明确复用、依赖与验收；不把 LobeHub 的全部功能自动纳入 Ferry。

事实来源：本仓库 ADR、当前会话/执行源码及本次用户需求。外部结构参考见 `docs/lobehub-source-analysis-2026-11-11.md`；外部模型、状态、权限与数据库结构不是本项目已确认需求。

## Existing Implementation / Reuse

- `crates/server/src/conversations.rs:73`：工作区权限与私聊/群聊可见性；记忆不能绕过来源权限。
- `crates/server/src/conversations/run.rs`：执行租约、候选原生 session、消息上下文和调度。扩展既有执行链路，不建第二个 Runner。
- `crates/server/src/conversations/messages.rs`：reply/recovery context；历史不作为重新执行命令。
- `crates/server/src/conversations/groups.rs`：显式成员、目标 Agent 与消息幂等。
- `crates/runner/src/agent/mod.rs` 与 `crates/protocol/src/agent.rs`：原生执行适配、进程生命周期与协议；若改协议，两端同步编译与兼容验证。
- `ADR.md`：Agent 与节点解耦、会话文本与执行事件分离、现有群聊不自动触发其他 Agent、复用模型档案。
- 管理资源复用共享列表/表单、权限、审计、加密资产、模型凭证与调用计费；先核查具体契约，再增加配置。
- 数据库沿用既有 SQLite/MySQL/PostgreSQL 支持，不直接引入上游 pgvector-only 表结构。

## Task Decomposition / Execution Mode

当前设计阶段 Direct，无子代理。实施阶段按共享权限、数据与执行契约先后拆分；独立验证单元是否委派届时另行评估，不让并行任务竞争公共迁移/协议/会话模块。

| 包 | 拟交付内容 | 依赖 | 验收重点 |
|---|---|---|---|
| A 记忆管理 | 显式保存、来源证据、作用域、编辑纠错、人工锁定、失效/删除、审计 | 权限与保留规则确认 | 无来源越权、修改并发、删除后停止召回 |
| B 记忆召回与整理 | 关键词与语义召回、预算内上下文注入、来源解释、可选提取/归并 | A；模型与 embedding 配置 | 已知问题命中、无关内容抑制、预算边界、嵌入故障降级、跨库 |
| C 技能资产 | 技能正文、版本、差异、证据、审阅发布、启停、历史恢复 | A；技能生效与审批规则 | 旧快照不能覆盖新版、执行快照可追溯、回滚边界明确 |
| D 学习闭环 | 完成轨迹生成候选、反馈、复盘、去重、提案与应用回执 | C；运行/计费/定时规则 | 暂停不算完成、学习不递归、失败不伪造经验、无证据不发布 |
| E 持久化协作 | 显式协作入口、负责人、顺序/并行子任务、交接、隔离上下文、汇总、取消 | C；协调状态机和用户责任确认 | 重复回调、完成屏障、父任务单次恢复、部分失败、超时与重启恢复 |
| F 会话与调度增强 | 会话分支/上下文选择；核查并补齐 ACK 不确定性、恢复失败、目录变化、撤权与设备替换处理 | E 的上下文/执行契约；现有机制核查 | UI 与模型使用同一分支、旧指令不重放、无双重执行、撤权生效 |

顺序：确认产品边界 → 完整 PRD/数据与状态契约 → A → B → C → D → E → F；F 的只读异常核查可提前进行，已有保证用测试证明，不重复建设。

## Design

三个独立概念必须保留：记忆是可引用事实，技能是版本化方法，执行许可来自当前授权。任何记忆或技能都不自动授予命令执行权限。

群聊默认保留既有显式目标规则。自动成员调度只能从用户选择的新协作模式进入；普通群消息与 Agent 回复不隐式触发协作。

候选学习结果与已发布技能分开。执行固定已选版本及上下文证据，不能因后台学习悄悄改变正在执行的任务。

原生会话与平台上下文分别记录来源与使用情况；不能宣称平台能撤回已经进入原生 CLI 历史的内容。来源删除/撤权后如何处置已派生事实及原生 session，必须写入保留与失效规则。

## 待确认的产品规则（推荐方案）

1. **分享与权限**：推荐个人记忆默认私有；工作区共享必须显式发布并具备管理权限；共享记忆不能包含发布者无权再分发的私聊内容。权限编码、发布主体、来源撤权后的行为待定义。
2. **自动化程度**：推荐支持用户开启自动提取及复盘，但新记忆先为候选，技能变更必须人工批准后发布；第一阶段关闭自动修改已发布运维技能。审批角色和触发人不在当前源码中定义，待确认。
3. **协作责任**：推荐新增显式协作模式，所有子任务继承发起人的授权上限与取消权；并行征询默认只读，写操作复用现有审批。负责人不能扩大子任务权限。审批等待、发起人离组/失权后的终止规则待定义。

这三项只是推荐，未作为已确认规则实现。自动共享、自动发布或扩大权限不能由开发者代定。

## Files to Change / Files to Add / Files Not to Change

- 拟改：现有会话上下文构建、调度接入、Agent/会话界面、权限/路由注册、i18n 及必要协议；精确文件集在逐包设计后锁定。
- 拟增：职责独立的记忆/技能/协作服务、实体、迁移与资源配置、相关测试；名称、字段、约束和 DDL 尚未定义，不编造为既有事实。
- 不改：无关运维业务、默认群聊语义、现有用户 CLI 全局配置；不搬运上游实现、不替换现有数据库/Runner。
- 当前工作区存在其他任务的未提交代码；实施前隔离分支/工作树，保留他人修改，不在共享脏文件上直接开始改造。

## Testing / Acceptance Criteria

- A/B：覆盖个人/群聊/工作区权限、来源撤权、删除、超长文本、空结果、冲突编辑、召回精度、模型/embedding 失败与预算截断；质量阈值由验收集确定，当前不虚构数值。
- C/D：覆盖重复事件、等待人工/工具、异常结束、证据不足、过期提案、并发更新、发布撤回、版本恢复及重复定时触发。
- E/F：覆盖成员失败/超时/取消、服务重启、重复和乱序回调、ACK 丢失、断线重连、session 失效、工作目录改变、离组撤权与旧客户端。
- 数据：增量迁移、历史数据保持、回退策略、各支持方言的真实数据库验证；不在共享实例执行未授权迁移。
- 页面：zh-CN/en-US/ms-MY、Desktop/Pad/Phone，默认/空/加载/错误/极端状态及完整核心流程。
- 基础检查：`cargo check --workspace`、`cargo test --workspace`、`npm run typecheck`、`npm run build`，并执行与每包对应的真实 API/Runner/浏览器验收。

## Risks / Out of Scope

- 模型调用和 embedding 增加延迟与成本；配置来源、配额、计费归属和定时频率须在 PRD 中明确。
- 跨会话知识可能泄露来源内容；向量检索与结果过滤都必须按当前授权处理。
- 删除/撤权传播、派生关系和原生 session 缓存不能只靠删除一行数据解决。
- 多 Agent 并发写同一目录仍受既有目录锁与授权限制；协作模式不能解除保护。
- 不包含模型权重训练、任意离线电脑唤醒、完整图谱产品、无限自治、IM 渠道接入，以及 LobeHub 其他无关功能。
- “所有值得借鉴的能力”指六包；高风险全自动发布不默认包含在内。
