# 洞察报告与代码走查方案

状态：洞察报告保留。2026-11-04 用户明确取消代码走查，移除其页面、菜单、API 与自动调度，仅保留历史数据和数据库迁移兼容；下文走查设计为历史方案，不再实施。此前功能随 0.2.0-alpha.1 发布，后续撤除以当前源码为准。

## 需求与入口

- 仓库：在代码洞察下新增「洞察报告」，可创建多个报告配置。
- 报告周期多选：日报、周报、月报、季报、年报。
- 分析维度单选：按人员、按应用；人员多选并支持昵称映射，应用覆盖多个仓库。
- 构建：新增「代码走查」，支持提交触发自动测试、AI 审计，或两者结合。
- 新增页面沿用共用列表、CRUD 表单、主题、六语言、sticky 操作区和权限体系。

## 源码核对与复用边界

- `repositories/analysis/insights.rs`：洞察配置、调度、来源选择、独立作者映射。
- `repositories/analysis/query.rs`：授权事实集合、仓库与 SHA 去重、人员/周期聚合；目前仅有日、周、月周期。旧报表过滤时间与分桶时间并非同一字段，不能直接拿旧查询冒充新报告一致周期语义。
- `repositories/analysis/insight_identity.rs`：洞察内人员归一化，映射不是全局名字替换。
- `repositories/monitor.rs`：已接收和保存仓库事件，支持轮询；没有查到业务走查规则到流水线的完整触发闭环。
- `pipelines/runs.rs`、`actions_run.rs`、`artifacts.rs`：执行、不可变配置快照、日志、产物、取消与执行器调度。
- 当前部署应用不是已经具备多仓库关联的业务项目；需要显式新增应用—仓库关系，不能靠名字推断。
- 未发现可直接复用的完整 AI 审计服务；模型连接、执行协议和结果导入属于新增能力。

## 一、洞察报告

### 配置与范围

建议报告绑定一个洞察作为数据源，复用它的仓库范围、已采集事实及作者映射。洞察负责采集，报告负责生成与阅读；从洞察详情提供创建报告入口，不另起一套采集器。

创建表单包含名称、来源洞察、报告维度、所选人员或应用、周期多选、报告时区、启停。首期固定周期调度，无需为每个日报/周报单独填写 cron；手动生成可选择历史期间。说明不作必填，不把作者映射 JSON 放到创建表单。

- 按人员：从来源洞察的归一化贡献者中搜索多选，显示昵称、关联姓名/邮箱；不是只能选 Ferry 登录账号。一个昵称对应多个 Git 身份时先归一化再统计。映射维护沿用独立映射页，报告提供跳转入口。
- 按应用：选择工作空间应用并关联一个或多个已授权仓库。应用—仓库关系独立保存，连接、分组、仓库选择复用现有组件，可使用动态分组。报告只读取来源洞察覆盖且当前有权访问的仓库，缺少关联或采集覆盖时明确提示。
- 若多个应用共享一个仓库，各应用可展示自己的范围；跨应用总览按仓库与 SHA 去重，不能把各应用合计简单相加。
- 人员范围首期是保存所选人员集合；A 组仅是报告名，不假设已经存在成员组织分组。后续动态团队成员需要独立明确的成员管理语义。

### 周期、快照与可追溯性

- 支持日、周、月、自然季度、自然年；默认采用工作空间时区，首次配置明确显示，允许修改。数据存储仍为 UTC，周从周一开始。
- 每种周期在结束后生成一份报告，例如昨日、上周、上月；建议留出30分钟采集缓冲。展示本周期实时预览，明确标记未结期。
- 新报告按作者时间确定贡献发生日期，并以同一字段计算时区边界与分桶，避免跨日漏算/重复。保留旧洞察查询兼容，不静默改变旧筛选语义。
- 每份报告保存期间边界、配置/映射/应用仓库范围版本、数据覆盖及生成时间。生成后默认不随映射变更静默改写；手动重新生成产生新修订。
- 生成时覆盖不足则显示「数据不完整」，列出失败或未同步仓库；可先保存部分报告，采集补齐后可重新生成，不伪装为零贡献。
- 报告生成不反向强制全量抓取；只复用事实并提交必要的缺失覆盖需求，沿用 SQL 队列、租约和幂等机制。

### 阅读界面与指标

列表显示名称、维度、对象数、周期、最近生成、下次生成、状态。详情顶部选择日/周/月/季/年及期间，下面为总览卡片、趋势、人员或应用对比、贡献明细；一份报告共用筛选，不堆叠多套独立搜索表。

人员报告：提交数、新增/删除/有效变更、活跃天数、参与仓库、周期趋势与前期对比；保留原洞察指标口径与明细跳转。应用报告：仓库覆盖、贡献人员、活跃度、变更主题、提交/测试/走查概况，保留原始证据链接。

「进度」首期展示研发活动及较上期变化，不能将代码行数、提交数换算为业务完成百分比。若要真实项目完成度，必须接入需求/里程碑/Issue 数据；这是独立范围，不能由 AI 猜测。AI 摘要为可选项，未配置模型时仍完整生成统计报告。

## 二、代码走查

### 配置与执行

一个走查配置可以选择多个仓库或动态分组，设置分支、文件范围、触发方式，以及自动测试/AI 审计两个独立开关。默认手动触发；创建时可开启提交触发，并明确显示该行为。建议首期事件支持 push 与手动；PR/MR 补充平台适配后再开启，不宣称天然全平台支持。

复用仓库监控事件；平台支持 Webhook 时接收事件，否则复用轮询。纯 Git 来源可轮询观察新 SHA，界面标明「检测到变更」，不把它说成完整平台提交审计。首次建立基线不自动回放全部历史。

链路：仓库事件 → 匹配走查规则与权限 → SQL 持久任务 → 固定仓库和 SHA → 现有流水线/执行器 → 产物导入 → 走查报告。幂等键包含规则版本、仓库、基线及目标 SHA、执行类型，重复投递不生成重复任务。失败保留错误并可重试；新提交不擅自取消正在执行的旧走查。

从测试/审计模板生成并关联专用流水线，用户可查看和编辑；不是让用户随意选一条不知用途的流水线。每次运行保留配置快照和代码基线，详情可以跳转流水线、运行、日志、产物与提交。模板应校验产物契约和权限，不能仅因流水线成功就判定审计通过。

执行器复用共享池、标签、系统/架构、指定主机及并发容量；没有匹配执行器时显示等待原因。HostAgent 是主机接入代理，Runner 是流水线执行资源，表单不混用名称。不新增服务器隐式执行任意仓库脚本的能力。

### 测试与 AI 审计结果

- 测试流程可以使用现有语言/构建模板或自定义命令，汇总通过/失败/跳过、用时，导入 JUnit 等结构化产物；未提供覆盖率文件则不展示虚假覆盖率。
- AI 默认审查固定 base/head 之间的增量 diff 与必要上下文；可手动发起指定 SHA 的全仓审计。文件与 token 预算明确，二进制、超限、排除及未审文件均显示，不能截断后宣称完整审计。
- 模型连接配置 API 地址、模型、加密凭据引用、超时、并发和预算。具体供应商适配单独标明支持范围，不承诺任何 API 都兼容。
- 测试步骤与带模型凭据的审计步骤隔离；AI 凭据不暴露给仓库测试脚本。仓库内容视为待分析数据，AI 不能因代码内指令调用工具或访问额外凭据。
- AI 返回校验后的结构化问题：严重程度、类别、仓库、文件/行号、说明、建议、证据、稳定指纹。无效路径/行号不直接展示成准确定位。
- 状态区分任务失败、测试失败、AI 完成发现问题、AI 完成未发现问题；不得用单个绿色成功替代所有结果。
- 问题允许标记待处理、已修复、忽略/误报并保留操作记录。后续走查用指纹关联旧问题，保留其首次/最近出现时间；未扫描到的范围不能自动标记已修复。
- 默认只记录和展示，不自动提交修复、合并代码、发布评论或向外部平台回写。是否阻断后续流水线使用显式规则，并在开启前展示条件。

### 走查页面

列表：名称、仓库范围、触发方式、测试/AI开关、最近运行、问题摘要、状态。详情：概况、运行记录、问题列表、配置；单次运行展示固定提交、测试摘要、问题定位、扫描覆盖、日志与快照链接。

## 三、持久化、权限与性能

新增业务记录建议包括报告定义/报告修订、应用仓库关联、走查定义/走查运行/走查问题及其出现记录。具体命名遵循既有实体/迁移规范。复用已有流水线运行、产物、通知渠道与加密存储，不复制日志系统或任务引擎。

首期使用现有 SQL 持久队列和租约，不增加 NATS JetStream 依赖；已有 NATS 可用于唤醒，丢失唤醒由数据库轮询补偿。采集、报告聚合、走查执行分别限流；生成报告不占用主机执行器。

报告查询复用授权事实集合与参数化聚合。新增季/年、时区边界及应用分组索引；避免每个人/每仓库一次远端请求或一条聚合 SQL。先验证真实查询计划和负载，再决定日聚合投影，不承诺永远不用调整 SQL。

新增独立报告和走查读写/生成/运行权限。任何创建、后台运行、历史查看和导出都校验当前工作空间、仓库与凭据权限；报告快照不能绕过撤权，也不能将创建者的私有仓库自动分享给其他成员。

## 四、实施与验收

本轮实现洞察报告及应用仓库关联、代码走查；两模块独立数据迁移、功能回归和验收，不修改已经发布的40标签。

必须覆盖：

- 一个作者多身份、昵称映射变更修订、同SHA跨分支去重、跨库范围与跨应用汇总。
- 日/周/月/季/年边界、跨年周、闰年、非整点时区/DST、停机后计划恢复与幂等补生成。
- 动态分组新仓库、来源覆盖不足/失败、映射冲突、撤权、快照历史及导出。
- 重复仓库事件、push/轮询/纯Git、固定SHA检出、执行器等待/断连/取消、重试、配置快照。
- 测试失败/产物缺失/格式错误、模型超时/限流/预算耗尽、恶意仓库提示、越权路径及日志凭据脱敏。
- AI问题去重、忽略保留、部分扫描不误判修复，以及所有失败状态的真实浏览器回归。
- 桌面/手机、六语言、主题、创建/编辑/详情与列表的完整可操作性。

本轮实施范围：报告复用一个洞察作为数据源、补充应用多仓库关联；五种周期均支持，固定周期自动生成并可追溯修订；代码走查复用专用模板流水线，首期手动/push触发，自动测试与AI审计可独立启用，默认不对外回写。
