# 集群编排与故障自愈设计

状态：设计稿，待用户审阅；未实现。清单编号 MARKET-P2-66 后续阶段。
上位文档：`docs/应用市场与集群模板设计.md`（模板/蓝图/驱动，P1–P2b 已交付）、`docs/prd/应用高可用拓扑与多部署驱动方案.md`（§8 各角色选主与恢复职责、§10 验收门槛）。

## 1. 意图

用户要求（2026-11-12）：

- 像 Helm 一样「选模板 + 填几个参数」就能部署；也能用 YAML 高级编辑。
- 部署 = **模板 + 我的部署目标**：例如部署 PXC / Redis Sentinel，选模板，填「几个主几个从」、「哪些节点可用」（按标签 `label=xx` 或指定主机 `host: xx`），由 Ferry 执行。Docker Swarm 和 K8s 原生支持节点选择；Native/Docker 由 Ferry 自己调度。
- 运行后要**健康监控、发现故障、自动迁移**，包括持久化数据：
  - 自带高可用的服务（PXC、Sentinel、NATS…）由服务自身切换，Ferry 负责补齐失败成员，不需要人工迁移数据；
  - 单体有状态服务出问题时，要能恢复或在新主机上启动，必要时用脚本迁移/恢复数据。
- 先整体规划好再分期实现。

## 2. 核心模型：三份文档，一个控制循环

```
模板（Blueprint，作者写）        部署规格（Deployment Spec，用户写）
  角色 / 实例数范围 / 端口          用哪个模板哪个版本 + 参数（values）
  健康检查 / 钩子 / 存储声明    +   每个角色几个实例
  支持的驱动 / 故障能力             用哪些主机（标签 / 主机名 / 主机组）
                                     存储、故障、备份策略
                     │
                     ▼  调度器（placement）
             放置结果（Placement，系统生成，可人工改）
               每个实例 → 主机（或 Swarm 节点 / K8s 交给集群）
                     │
                     ▼  编译器（已实现：按驱动生成每主机产物）
             修订（Revision）：每主机 ferry/v2 Application
                     │
                     ▼  执行器（已实现：预览 / 逐主机执行 / 回滚）
             运行中的实例
                     │
                     ▼  协调器（Reconciler，新增，持续运行）
   观测（主机心跳 + 实例健康 + 服务级健康）→ 对比期望 → 动作（重启 / 替换 / 恢复 / 告警）
```

对应成熟方案：模板 ≈ Helm chart / Nomad pack；部署规格 ≈ Helm values + Nomad job 的 group/constraint/count；调度器 ≈ Nomad scheduler（Native/Docker）或交给 Swarm/K8s；协调器 ≈ Nomad 的 reschedule + K8s controller。

## 3. 部署规格（`deploy.yaml`）

用户通过向导填写，向导即这份文档的表单；「高级」模式直接编辑 YAML，二者双向同步。存储在部署记录中，每次修订快照。

### 3.1 示例：PXC 三节点

```yaml
apiVersion: ferry/deploy-v1
template: { source: official, package: pxc-cluster, version: 1.0.0 }
driver: docker              # native | docker | compose | stack | (k8s 未来)
values:
  root_password: { secret: PXC_ROOT_PASSWORD }   # 引用工作空间变量，不写明文
  innodb_buffer_pool_size: 1G
roles:
  pxc:
    instances: 3
    hosts:
      selector: { tags: [db, ssd] }               # 同时带 db 与 ssd 标签的主机
      spread: { by: tag-prefix, prefix: "zone:" } # 尽量分散到不同 zone:* 标签
    storage: { class: local, size: 50Gi, path: /data/pxc }
failover:
  mode: auto                 # off | alert | auto
  hostDownAfter: 2m          # 主机失联多久判定故障
  maxConcurrent: 1           # 同时只替换一个成员（保仲裁）
backup:
  schedule: "0 3 * * *"
  target: platform-s3        # 平台 S3 存储
  keep: 7
```

### 3.2 示例：Redis Sentinel 一主二从三哨兵

```yaml
template: { source: official, package: redis-sentinel, version: 1.0.0 }
driver: stack
manager: { host: swarm-mgr-1 }
values: { password: { secret: REDIS_PASSWORD } }
roles:
  redis:
    instances: 3            # 模板规定：第一个为初始主，其余为从（模板 initialRole 规则）
    hosts: { selector: { tags: [cache] } }
  sentinel:
    instances: 3
    hosts: { colocateWith: redis }
failover: { mode: auto }
```

### 3.3 字段规则

| 字段 | 说明 |
|---|---|
| `roles.<r>.instances` | 模板 `min/max/odd` 约束内 |
| `hosts.selector.tags` | 主机必须同时带这些标签（复用现有主机标签）；`hosts.names` 指定主机；`hosts.group` 指定主机组；三者可组合，取交集 |
| `hosts.spread` | 软约束：按标签前缀分散（如 `zone:a/zone:b`），不满足时警告不阻断 |
| `colocateWith` / 模板 `distinctHosts` | 硬约束 |
| `storage.class` | `local`（主机本地目录/卷）、`shared`（NFS/Ceph 等共享存储挂载点，主机需带 `storage:shared` 能力标签）、`none` |
| `failover.mode` | `off` 不处理；`alert` 只告警；`auto` 按 §6 自动处理 |
| `backup` | 模板声明了备份钩子时可用；存到平台 S3 或指定存储 |

Swarm：`hosts.selector.tags` 同时映射为 Swarm 节点 label 约束（节点必须是已登记主机，见 P2b）。K8s（未来驱动）：映射为 `nodeSelector` / `affinity`，存储映射为 StorageClass + PVC。

## 4. 模板扩展（作者侧）

在现有 Blueprint 上增加（均为可选，缺省即「不支持该能力」）：

```yaml
roles:
  - name: redis
    initialRoles: { first: master, others: replica }   # 「几主几从」由实例序号决定初始角色
    persistence:
      volumes: [{ name: data, path: /data, critical: true }]
      replication: native        # native（服务自己复制）| none（单体）
    failover:
      replace: supported         # 能否在新主机上补一个成员加入原集群
      singleton: restore-from-backup | restart-on-shared-storage | manual
    hooks:
      join:     ["sh", "/etc/ferry/join.sh"]        # 新成员加入
      leave:    ["sh", "/etc/ferry/leave.sh"]       # 移除成员（优雅退出 / 清理元数据）
      promote:  ["sh", "/etc/ferry/promote.sh"]     # 需要人为提升主时（Sentinel 不需要）
      backup:   ["sh", "/etc/ferry/backup.sh"]      # 输出数据快照到 stdout 或指定目录
      restore:  ["sh", "/etc/ferry/restore.sh"]     # 从快照恢复
      healthy:  ["sh", "/etc/ferry/healthy.sh"]     # 服务级健康（如 PXC wsrep_ready、Sentinel 有主）
```

钩子运行在实例容器内（Docker/Swarm/K8s）或实例进程环境（Native），可用 `.Instance/.Role` 模板变量。官方模板（PXC、Redis Sentinel、NATS、Nginx、XXL-JOB、Ferry）逐个补齐钩子并按 §8 验收。

## 5. 调度（放置）

### 5.1 谁来放置

| 驱动 | 无状态角色 | 有状态角色 |
|---|---|---|
| Native / Docker | **Ferry 调度器** | Ferry 调度器，结果固定（身份 = 实例序号 + 主机 + 卷） |
| Compose | 单主机，无需调度 | 单主机 |
| Swarm | 交给 Swarm（约束来自 selector） | Ferry 选节点并固定（已实现 `node.id==`） |
| K8s（未来） | Deployment | StatefulSet + PVC；节点由 K8s 选，Ferry 只给 selector |

### 5.2 Ferry 调度器（Native/Docker）

- 候选主机 = selector 匹配 ∩ 在线 ∩ Linux ∩ 满足资源（取主机监控的 CPU/内存/磁盘余量，模板 `resources.requests` 估算）。
- 硬约束：`distinctHosts`、`colocateWith`、端口不冲突、存储类可用（`shared` 需能力标签）。
- 打分（类似 Nomad）：spread 标签分散优先 → 已有该应用实例少的主机优先 → 资源余量多的优先；同分按主机 ID 稳定排序，保证结果可复现。
- 输出放置结果；用户可在向导里逐实例修改；不满足约束时说明原因（例如「NATS 需要 3 台带 cache 标签的在线主机，当前 2 台」）。
- 放置结果进入修订快照；回滚使用旧放置。

## 6. 健康与故障自愈（协调器）

### 6.1 观测信号

| 层级 | 来源 | 现状 |
|---|---|---|
| 主机 | Runner 心跳 / SSH 探测（`hosts.seen_at`、主机监控） | 已有 |
| 实例进程 | Docker/Swarm 任务状态、systemd 状态、就绪/存活检查 | 已有（部署执行与健康检查） |
| 服务级 | 模板 `healthy` 钩子；或监控模块 HTTP/TCP/运行时检查 | 监控模块已有，**蓝图部署尚未接入** |

### 6.2 故障判定

- 实例不健康：驱动自身先重启（Docker restart / Swarm / systemd）；连续失败超过阈值 → 升级为「实例故障」。
- 主机故障：心跳超时超过 `hostDownAfter` 且**二次确认**（从 Ferry 服务端和至少一台同集群主机探测都不通）才判定，防止网络抖动误迁移。
- **隔离（fencing）先于迁移**：判定后先尝试停掉旧实例（主机可达时）或标记旧主机为「隔离」，旧主机恢复上线时由协调器先停掉其上被替换的实例，避免双主/脑裂。

### 6.3 按工作负载类型处理

| 类型 | 例子 | 自动动作 | 数据 |
|---|---|---|---|
| A 无状态 | nginx、XXL-JOB executor | 在其他候选主机重建实例，更新成员列表（依赖它的配置按批重渲染） | 无 |
| B 有状态 + 服务自带复制 | PXC、Redis Sentinel、NATS JetStream、Redis Cluster | **服务自己切换**（选主/提升）；Ferry 在新主机上**补一个成员**：`leave`（清理旧成员元数据）→ 新实例启动 → `join` → 等服务级健康（数据由服务同步：PXC SST/IST、Redis 全量复制、NATS 副本追平）→ 更新其他成员配置。一次只换一个，确认仲裁安全 | 由服务复制，Ferry 不搬数据 |
| C 单体有状态 + 共享存储 | 单机 MySQL 数据在 NFS/Ceph | 隔离旧实例 → 在另一台能挂同一共享存储的主机启动 | 数据不动，挂载切换 |
| D 单体有状态 + 本地存储 | 单机 MySQL/Redis/PostgreSQL 数据在本地盘 | 默认**只告警**；策略 `restore-from-backup` 时：在新主机用最近一次备份恢复后启动，明确告知 RPO（= 备份间隔）；旧主机恢复后数据保留待人工处理 | 备份恢复，有数据丢失窗口 |

原则：**不会自动做可能丢数据的事，除非部署规格明确允许**（D 类 `auto` 必须同时配置 `backup` 并在向导中确认 RPO）。

### 6.4 备份与恢复

- 模板 `backup`/`restore` 钩子 + 部署规格 `backup.schedule`：协调器定时在实例里执行备份，产物存平台 S3（已有存储能力），按 `keep` 保留；备份记录可在部署详情查看、手动恢复到新实例。
- 有状态服务 B 类也可开备份（防误删，与故障迁移无关）。

### 6.5 动作安全

- 每个自动动作都生成一个修订（类型 `auto-replace` / `auto-restore`），走现有执行器、可审计、可回滚到之前的放置。
- 并发限制：同一应用同时最多一个自动动作；`maxConcurrent` 限制成员替换个数；替换前检查仲裁（例如 3 成员 PXC 已失去 1 个时，不在第二个也不健康的情况下继续动）。
- 冷却时间：同一实例两次自动迁移间隔不少于 10 分钟；连续失败 3 次转人工。
- 全停（全部成员同时失联）不自动处理，转人工恢复流程（PXC 需选择最安全的引导节点）。

## 7. 界面与交互

1. 应用市场 → 选模板 → **部署向导**：参数表单（来自 `parameters.yaml`）→ 每个角色实例数 → 主机选择（标签 / 主机名 / 主机组，实时显示匹配主机）→ 存储与故障、备份策略 → 放置预览（可逐实例改）→ 部署。
2. 「高级」切换：同一份 `deploy.yaml` 的 YAML 编辑器，与表单双向同步；校验错误标在行上。
3. 部署详情：拓扑视图（角色 → 实例 → 主机，健康状态、当前主/从）、自动动作时间线、备份列表。
4. 想改模板本身 → 「导入到本空间并编辑」（已有导入能力），再从自己的副本部署。

## 9. 不做 / 边界

- 不自研通用容器调度器去替代 Swarm/K8s：Swarm/K8s 下无状态调度交给它们；Ferry 只在 Native/Docker 做放置。
- 不在主机之间复制块设备（不做 DRBD 类方案）；单体本地数据只通过服务备份恢复。
- 不自动处理全集群同时失联；不做跨数据中心选主。
- 外部入口（VIP / 负载均衡器 / DNS）不由 Ferry 自动切换，模板通过 `endpoints` 提供客户端发现方式（Sentinel / 多地址）。
