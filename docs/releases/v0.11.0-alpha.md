# v0.11.0-alpha

Date: 2026-11-24

## Rooms with several developers and their Agents

- Every room member can add their own Agents. The same Agent may be added once
  per member and is shown as "Name (Member)". An Agent always works as the
  member who added it, with that member's permissions and hosts, whoever
  addresses it.
- Approval mode is set per Agent by the member who added it. A room-wide mode
  no longer loosens another member's Agent.
- Agents can hand work to each other in the room without approval (for
  example an API Agent telling the app Agent about a contract change). Each
  Agent sees the other room Agents and their messages. A chain of more than 10
  Agent-to-Agent messages, or a room where a member turned relay off, waits for
  a member to continue.
- Different Agents in a room run at the same time on their own hosts; one Agent
  still runs one task at a time.
- When the member who added an Agent leaves the room or loses access, that
  Agent is paused or removed and its waiting tasks are cancelled.
- Claude Agents may use their own subagents inside a task, under the same tool
  and directory limits.

## Pipelines and workflows in rooms

- Pipelines and workflows created from a room are linked to it and appear as
  threads above the messages; runs started from the room appear in the
  resource's thread. Thread results stay out of the main feed and open in a
  side panel (full screen on phones) where members can discuss them.
- When a run started from the room finishes, the result is posted to its
  thread and the Agent that started it continues automatically.
- Deleting a room never deletes pipelines, workflows or runs; only the links
  are removed. Pipeline and workflow pages show the rooms that created them.

## Workflows

- An Agent node prompt that uses the current item ($json, $binary or
  $input.item) is rejected when saved, with an explanation: the node runs once
  over all inputs, which are appended to the prompt automatically. Existing
  workflows report the same cause when run. The Agent node description tells
  AI authors to write literal instructions.
- The workflow list has the same group sidebar and group column as the
  pipeline list, including group ordering.

## Workspaces and workflows

- Workspace name, avatar and business timezone can be maintained independently
  from the workspace settings. A schema migration adds the workspace avatar
  column; existing workspaces keep their names and timezones.
- Workflow execution history shows clearer per-node progress, a usable panel
  height and logging, and prompt guidance for Agent nodes.

## Navigation and conversations

- Keep application navigation and the open conversation when moving between
  pages, including host detail pages.
- Format dashboard timestamps before inserting them into translated text.
- Resume conversation and list loading after the browser suspends a background
  tab or page. Requests that stalled while hidden restart on return, late replies
  from an earlier cycle are ignored, and messages are never resent. A renewable
  session expiry keeps the current content and drafts; real access denial still
  clears them.

## Mobile (H5) layout

- Keep the chat feed, composer and navigation inside the visible viewport on
  phones and tablets, including on-screen keyboards, landscape, safe areas and
  enlarged text.
- Compact messaging layout on phones: a single conversation title bar, a
  one-line composer that grows with its content, and a plus menu for
  attachments, voice, mentions, stop and shortcuts. Filters, search, approval
  settings and workspace, account and appearance controls are in the More panel.
  Pending approvals stay visible. Desktop layout is unchanged.

## Installation

Server-side upgrade applies the migrations automatically: workspace avatars,
room Agent sponsors and approval modes (existing room Agents belong to the room
owner and keep the room's approval mode), and room thread tables. The Web
interface changes take effect after a server update. Runner hosts need this
version for Claude subagents.
