# v0.10.8-alpha

Date: 2026-11-22

## Workspace business time

- Workspace creation suggests the browser's IANA timezone and lets the creator change it. A confirmed workspace timezone governs business calendars, schedules, report periods and date display/input. Backend timestamps and database sessions remain UTC.
- Existing workspaces remain explicitly unconfirmed until an administrator saves a timezone. Upgrade does not guess a timezone or rewrite historical timestamps and resource configurations.
- Saving a workspace timezone recomputes future cron and code-insight schedules transactionally. Workflow executions freeze their effective timezone and node clocks so recovery does not switch timezones halfway through a run.
- Code-insight date filters and day/week/month aggregation follow the confirmed workspace calendar, including daylight-saving transitions. Calendar aggregation remains in SQL on SQLite, PostgreSQL and MySQL without requiring database timezone tables.
- AI runtime context includes the actual saved workflow clock. The platform does not ask the model to infer the current date from its training knowledge.
- New command and terminal processes receive their execution's business timezone without changing the host OS. Older Runners must be upgraded for per-process timezone support; SSH hosts must accept the `TZ` environment request.

## Workflow diagnosis

- Fixed the published batch-Agent example, which used unavailable current-item `$json`. Agent input items are supplied automatically; batch expressions can use `$input.all()`.
- Documented complete expression-preview requests, `items`/`upstream`, batch selections and zero-based JSON Pointer node paths. Rejected previews return instructions for correcting the request.
- Expression errors occurring before a node starts now retain their public diagnostic in the encrypted execution context. Execution details expose the specific path and localized error instead of only `node_failed`.

## Mobile release assets

- Tag releases now wait for Android and iOS builds and collect versioned mobile packages alongside desktop and Runner assets. Package identity, version, architecture, contents and SHA256 checks are part of collection.
- Android APKs are debug-signed acceptance builds. The iOS device IPA is unsigned and requires an Apple team and provisioning profile before physical-device installation. A separate simulator package is provided. This release does not represent App Store or Play Store publication.

## Upgrade notes

- The workspace timezone column is additive and nullable. Old clients omitting the field retain explicit unconfirmed compatibility. Automatic migration rollback refuses to discard business-time configuration.
- Upgrade every server replica before confirming workspace timezones. New workflow execution contexts persist the effective zone and require this release for recovery; do not route those executions to older server workers.
- Keep backups of the database, file-storage data and encryption keys. The encrypted file-format compatibility boundary introduced in v0.10.7-alpha still applies: older releases cannot read newly written chunk-authenticated files.
- A successful software release does not prove a particular workflow produced a PDF or delivered a group notification. Check the execution record and delivery result before enabling a scheduled report.
