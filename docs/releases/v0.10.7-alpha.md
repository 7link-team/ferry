# 0.10.7-alpha

## Upgrade compatibility

This version introduces chunk-authenticated encrypted file storage. It reads existing files without rewriting them, but older servers cannot read files newly written in this format. Upgrade all servers and workers together before allowing new writes. After new-format files have been written, do not directly downgrade to an older server. Keep a consistent backup of application data, database and encryption keys before upgrading.

Publishing this release does not upgrade an existing deployment. Use the deployment's existing upgrade and backup procedure. Running tasks must be allowed to finish under the coordinated upgrade procedure.

## Changes

- Native Android and iOS clients configure a server on first launch, retain the selected server and operate only as remote clients. Desktop retains service and client modes. The business interface comes from the connected server.
- Conversation Agents support API and CLI models with separate model context per conversation/Agent pair. Model-generated first introductions, conversation instructions and platform approval policy use maintained configuration.
- Conversation execution details, approval/question handling, pending counts and large tool-result discovery improve continuity and readability. Workflow tools expose definition examples and paginated node discovery.
- Workflow Agent nodes resolve execution per node: API models execute on the server; CLI models use their eligible execution hosts. Monetary admission limits are removed while usage accounting and authorization remain.
- File consumers use the shared storage service and streaming paths. Configurable resource policies default to unlimited admission while preserving authorization, protocol validation and connection liveness checks.
- Host terminal forwarding, reconnection and layout handling improve long-running command interaction.
- Account email verification displays actual verification evidence. Workspace member invitations can be sent by email; member lists reuse the existing avatar and profile gender. Workspace selection refreshes its data when opened, and successful saves refresh data without replacing the whole application shell.
- Shared form scrolling keeps sticky actions reachable in ordinary resource forms and deployment wizards. Code insight refresh retains reading position and expanded content.

## Mobile distribution

The mobile acceptance bundle contains Android arm64/x86_64 APKs, an unsigned iOS device IPA and an Apple Silicon simulator application. Android APKs use a debug certificate; they are not store releases. The iOS device IPA requires an Apple signing identity and provisioning profile before physical-device installation. No default deployment server is embedded.

## Validation boundaries

Release publication is gated by the build workflow's required checks and runtime acceptance jobs, including signed desktop/Runner artifacts. Server images are tested and published separately for AMD64 and ARM64. Existing ignored tests and the historical documentation validator's fixed node-count limitation are not represented as newly passing tests. See the [documentation index](https://github.com/7link-team/ferry/blob/v0.10.7-alpha/docs/README.md) for design, operating and historical records.
