# v0.10.12-alpha

Date: 2026-11-23

## Mobile client updates

- Connection settings now show the installed client version and a Check for
  updates action. Release notes, available/current/error states, download
  progress and retry controls are localized in Chinese, English and Malay.
- Android selects the newer APK for the current ABI and configured release
  channel, downloads in chunks and verifies its SHA256 and size. Native code
  checks package identity, increasing versionCode and the installed signing
  certificate before opening the Android installer. Installation requires the
  user's system permission and confirmation; it is not silent installation.
- iOS checks for a newer version and opens the configured HTTPS TestFlight,
  App Store or enterprise distribution landing page. When no distribution URL
  exists, the client explains the limitation and disables the install action.
  An unsigned IPA is not directly installable.
- Native update commands are restricted to the bundled connection document;
  remote workspace content receives no update privileges. Desktop keeps its
  existing signed updater and shares only release configuration/types.
- Optional persistent Android signing is configured with a complete set of four
  GitHub Actions secrets. Without them, builds remain debug-signed acceptance
  packages and cannot guarantee upgrades across CI runs. No production key or
  iOS distribution URL is supplied by this release.

See [configuration and acceptance scope](../plans/2026-11-23-mobile-client-updates.md).
Clients predating this feature need one manual installation of a compatible new
build before they can use its update controls. Signing mismatches are rejected;
the client never uninstalls an app or removes its user data to force an update.

## Test coordination

- Keep a queued provider test future polled while its cancellation state is
  written. Pausing that future could hold database work and cause a connection
  acquisition timeout in CI. Existing admission/cancellation assertions and
  timeouts remain unchanged; no production concurrency policy changes.
- Native Android acceptance uses WebView-supported CDP operations, retains the
  existing connection/recovery assertions and verifies remote update-command
  isolation. HttpOnly session verification remains enabled.
