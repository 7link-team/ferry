# 部署与数据导入

## 支持的部署目标

| 模式 | 目标与要求 | 更新与健康检查 |
|---|---|---|
| Compose | 已安装 Docker Compose 的 Linux 主机 | recreate；支持容器健康检查和部署就绪检查 |
| Docker | 已安装 Docker 的 Linux 主机 | 每服务一个容器；recreate |
| native | 已安装 systemd 的 Linux 主机 | 每服务一个 unit；ExecStartPost 检查与失败重启 |
| Swarm（stack） | 已加入 Swarm 的 manager 主机 | 支持滚动更新、期望副本数及任务就绪检查 |

上述模式可使用 Runner 或 SSH；执行身份需有管理目标服务的权限。K8s／Helm 暂缓。保存应用时校验模式能力，例如 native／Docker 不支持单机多副本，Swarm 不支持 Compose 的 depends_on 启动顺序。持久卷是节点本地数据，不提供跨节点复制。

配置先渲染、预览，再确认执行。预览与提交之间目标产物或关联配置变化时会要求重新预览。应用历史保存固定镜像摘要、完整执行产物及加密变量／配置快照，回滚不重新读取当前模板或当前密钥。

主机组只包含直接成员，按主机 ID 逐台执行。预览后成员变更会使预览失效；入队后固定成员，不受后续移组影响。首个失败即停，已成功主机不自动回滚。详情显示逐主机结果及当前版本，回滚采用历史目标列表。存在失败或部分成功时，先回滚或重新部署成功，再使用定时重启。

## 构建产物与配置文件

流水线定义的 `artifacts` 填写构建工作目录下的相对文件路径，例如：

```json
{
  "workdir": "/tmp/build/{{run}}",
  "steps": [{ "name": "build", "run": "make" }],
  "artifacts": ["dist/service"]
}
```

成功执行后服务端流式归档文件，记录 SHA-256、大小和文件模式。声明文件缺失会使构建失败。构建产物可下载；native 模式使用归档的可执行文件，不从之后可能改变的构建目录取文件。

```yaml
services:
  - name: api
    artifact:
      source: pipeline
      pipeline: "流水线 ID 或唯一名称"
      path: dist/service
    files:
      - path: /etc/service.conf
        fromTemplate: "配置文件模板 ID 或唯一名称"
        values:
          port: 8080
```

配置模板使用 `{{ .Values.port }}` 参数。标记为密钥的参数填写已有变量名；预览仅显示引用，实际内容随部署快照加密保留。目标配置文件为只读挂载；Swarm 通过版本化 secret 分发到任务节点，不能使用 manager 本地路径冒充远程节点挂载。native 的环境文件会保留，以便主机重启后仍能启动服务。

## CSV／XLSX 导入导出

普通可创建资源支持“下载模板 → 上传 → 预览 → 确认新增”。每次最多 1000 行、8MB，XLSX 解压内容最多 32MB。模板第一张工作表为数据表，第二张为字段说明。复杂定义、字典项、参数及权限／标签数组使用对应字段的 JSON 或文本格式；引用填写当前空间 ID。

导入只新增，不自动覆盖现有记录。预览执行相同的权限与业务校验，但不保留资源和审计变更；错误注明原始行号。全部通过后才能确认，提交时再次检查权限和引用；任一行失败则整批回滚。重复或并发确认不会重复创建。

密钥列在预览中遮蔽，待确认数据加密并绑定当前用户、工作空间及资源。取消会删除待确认数据；成功提交后清空待确认密文。默认不设置自动清理期限。上传的 XLSX 不能包含公式。

导出包含当前筛选及排序下的全部记录，不限于当前页面；沿用列表读取权限和公开字段，不导出凭据密钥或秘密变量值。CSV 对公式开头的文字加保护前缀，XLSX 使用文本单元格。XLSX 单元格最长 32767 字符，较长的定义请使用 CSV。历史记录、成员列表等只读资源支持导出，不支持导入执行记录或代替成员邀请。

主机的 `tag_ids` 使用 ID 字符串数组。编辑省略该字段会保留关联，显式 `[]` 会清空；引用中的标签不能删除，先从主机移除后再删除。
