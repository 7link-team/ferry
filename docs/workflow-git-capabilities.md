# 工作流 Git 操作与仓库连接复用

本轮依据：用户要求补齐 Codeup、GitHub、GitLab、纯 Git 常用操作；用户已确认构建流水线与节点工作流统一连接入口，认证强制复用，操作参数独立配置。沿用仓库连接、声明式集成执行器、SSH/Agent 通道、Actions checkout，不新增连接或凭据模块。

## 配置与执行

节点工作流默认选择已有仓库连接，然后选择仓库和操作参数。服务端读取连接的平台、API 地址、组织和加密凭据，复用 OAuth 刷新；不接受节点参数覆盖连接地址、组织或认证。GitLab PAT 与 OAuth 使用各自认证头，API 前缀保留；Codeup 根据连接组织配置使用中心版或 Region 版路径。

新建平台 API 节点必须选择已有仓库连接，不再提供独立令牌入口。共享选择器支持就地创建连接，复用仓库连接表单与 OAuth 流程，成功后留在当前编辑器并自动选中；平台 API 创建连接的平台固定为当前平台。私有 Git 网络操作使用连接认证；公开 Git 可显式选择免认证 HTTP(S) URL，禁止 SSH、URL 用户名/密码、查询参数及片段，运行时再次校验表达式结果，并隔离主机全局认证与仓库本地认证配置。本地 Git 操作不要求连接。

旧独立 API 配置和主机 Git 认证不静默迁移：仅同一已保存工作流、同一层级节点 ID/类型及原认证字段保持兼容。更换认证必须选择连接；复制或新增节点不继承旧认证豁免。保存与执行均检查连接空间/权限/状态，连接失效不回退到旧凭据。连接认证优先于残留旧参数。原生 Actions YAML 和第三方 Action 保持兼容，不改写其认证方式。

构建流水线提供命令、克隆代码、Action 三种步骤类型；克隆表单复用已有连接/仓库/分支。任务设置内支持选择多个仓库、多个分组及跨连接选择。分组在编辑时展开为当前仓库快照，重叠分组去重；不会在运行时自动包含未来新增仓库。生成独立稳定步骤 ID 和独立目录；已有步骤、YAML 注释与扩展字段保留。原生 GitHub checkout 参数保留在高级选项。

操作数量是声明数，不是平台功能覆盖率。GitHub/GitLab/Codeup API 不完全等价。未覆盖：所有平台管理 API、仓库删除/转移、成员权限、Webhook 管理、分支保护、完整评审讨论、发布附件、子模块、worktree、bisect、交互式 rebase、强制 push/clean 等。用户要求的完整 Git 能力仍不能以本轮数量宣称全部完成。

Git 写操作使用当前主机目录。commit/revert/cherry-pick 显式指定作者；commit 只提交已暂存改动；pull/merge 仅快进；push 仅将 HEAD 推到指定分支，不强制覆盖；分支删除只允许已合并分支。reset 的 soft/mixed/hard 明确选择，默认示例 soft，hard 的丢弃行为在字段标签说明。失败原样记录为失败，不自动清理冲突现场、不隐式重试写操作。

网络 Git 禁用 file/ext 协议及 HTTP 重定向。连接凭据通过既有流水线 credential helper/SSH 私钥私密文件传输，复用主机临时目录清理；不写入脚本、命令参数、图定义。认证 Git 不采集未经清洗的实时输出，完整 stdout 清洗后作为节点结果保存；HTTP 节点沿用响应上限、重定向禁用、敏感回显拒绝及加密调用账本。

## 接口事实依据

- 项目实现：`repositories/auth/{connection,provider}.rs`、`pipelines/{actions,actions_run/checkout,runs}.rs`、`workflows/{integration,host,graph}.rs`。
- 唯一声明：`src/shared/workflow-contracts/workflow-integration-nodes.json`，前后端共用，不从 docs 导入源码。
- [Codeup 新版 API](https://help.aliyun.com/zh/yunxiao/developer-reference/codeup/)：分支、文件、代码库标签、提交、提交状态、代码比较、合并请求目录。采用 `x-yunxiao-token`，不混用旧 AccessKey SDK。新增接口逐项以官方文档的 HTTP 方法、path/query/body 位置和字段名核对。
- [GitHub REST OpenAPI](https://github.com/github/rest-api-description/blob/main/descriptions/api.github.com/api.github.com.json)。文件写入使用 Base64，更新/删除需要当前 blob SHA；Git 引用创建需完整 `refs/heads/…` 或 `refs/tags/…`。
- [GitLab 官方 API 文档](https://docs.gitlab.com/api/)：branches、tags、repository_files、commits、repositories、merge_requests。
- 抓取的官方原文、请求映射核对与测试日志保留在本地 `data/maintenance/git-capabilities-20261109/`，不提交令牌或用户数据。

## 节点构建入口补正（2026-11-09）

用户反馈节点工作流找不到克隆且不能构建。依据现有 Git clone 声明、host.command 契约及 hosts 运行通道，本期将所有主机 Git 与命令放入“代码与构建”，搜索仍跨分类；不新增另一套克隆执行器。主机命令执行一整个输入批次一次，使用现有集成调用账本防重发、SSH/Agent 容量/租约/授权与取消机制；结果含 stdout、exit_code=0、execution_host，失败沿用节点失败与日志。

命令表单为解释器下拉、脚本文本、结构化输入环境变量；MESSAGE 映射 FERRY_INPUT_MESSAGE，值安全引用而不拼脚本。当前解释器仅 sh/auto（auto→sh，Windows Git Bash），input_assets 非空与 PowerShell 在运行前拒绝，不伪装支持。沿用每节点120秒/输出1MiB/日志256KiB上限。构建工具由目标主机安装，克隆与构建必须选择同一具体主机并显式 cd，主机组不保证目录跟随；不自动传输目录、不新增制品发布、容器隔离、依赖安装或多机工作目录调度。退出非零失败，不自动重跑未知执行。

沿用上文评审矩阵：无新模型/DDL/迁移/权限名；host.command 从既有设计接入，旧未支持Shell不自动改写；读/编辑差异与四宽度沿用共享表单。新增六语分类/字段/限制提示；默认、空命令、非法键/插值/超长输入、非法Shell/文件输入、主机权限/失联/失败及成功需验证。Desktop/Pad/Phone均可从同一分类选克隆和命令，表单单列/自身滚动，标题/关闭与核心操作保留；Figma与原生软键盘无，不宣称已覆盖。

## 克隆表单与分支布局补正（2026-11-09）

本期依据用户反馈及现有Git/分支端口契约：应用与集成→Codeup→仓库新增克隆入口，声明git.provider=codeup，复用通用克隆执行器；表单和服务端保存/执行均限制为同空间Codeup连接。通用Git克隆保留跨提供方与公开免认证入口。连接模式选择仓库带入URL，地址仅展示，不重复要求手输；切换连接清除旧地址，新建节点不选择示例连接/地址。免认证和旧Git模式保留地址输入。

路径为执行主机绝对路径，六语帮助列Linux/macOS/Windows Git Bash示例，明确需要Git及sh、同一具体主机、新目录；本期不新增跨系统逻辑工作目录或PowerShell支持。商业Codeup端点和原生macOS执行未实跑，不冒充验收。

分支节点右侧每个输出有独立添加按钮，所选端口传入既有addAdjacentNode，底部继续添加保留分支选择器。出口、连线、选择器及执行视图使用同一标签：if满足/不满足，switch使用cases[index].key，fallback未匹配。端口ID不改，移动/整理只改位置不改执行语义。整理布局包含下向关系时按拓扑保留上下/左右约束并消除卡片碰撞；多父节点汇合以所有上游最小间距共同约束定位，无法同时对齐所有不同列父节点时保留连接身份。无新模型/DDL/迁移/权限或自动远程写入。

沿用上文全状态/权限/六语/三类尺寸评审矩阵；新增验收：Codeup子入口与提供方过滤、仓库带入/切换清空/免认证地址、第二分支按钮及标签、拖动后整理方向和分支身份、布局幂等与无碰撞。Figma与原生软键盘未提供。
